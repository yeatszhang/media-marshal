# 商业模式、内容运营与付费策略

更新日期：2026-10-25。本文记录产品与商业方向，供后续规划和验证使用；当前桌面范围与实施状态以对应 OpenSpec 变更和发行说明为准，旧版本能力见[旧工程用户手册](../legacy/user-guide.md)。本文中的桌面端、官方托管 API、付费套餐与托管通知是当时的规划，不表示已经上线。

## 核心决策

**便捷、完整的媒体整理能力免费；使用官方提供的识别与整理 API 按需付费；后续通过消息通知等持续服务扩展会员价值。**

免费工具帮助用户形成持续整理的习惯。官方 API 提供免配置的识别服务，减少复杂文件名、作品别名和季集歧义带来的人工处理。会员在此基础上提供有持续交付价值的服务。

桌面端与自托管端遵循相同的免费边界。桌面安装、基础整理和后续软件更新不以购买桌面授权或续费维护为前提。此前讨论过的桌面买断和更新续费方案不作为当前商业方向。

已确定的是免费与付费边界、三个推进阶段，以及后续扩展消息通知的方向。价格、额度、会员权益、通知渠道和阶段验收数值仍需验证。

## 用户与付费价值

产品 Slogan 统一为「你的本地媒体库」，总体定位见[产品定位与运营方向](./positioning.md)。通过现有电脑和移动硬盘，帮助用户低成本建立自己的媒体库并搭建家庭影院。内容运营覆盖初次搭建到持续收片的用户；官方 API 的首批验证优先选择已经使用 Emby、持续从网盘客户端下载影视，但仍需手动整理的用户。

| 用户 | 免费工具的价值 | 官方服务的潜在付费理由 |
| --- | --- | --- |
| 初次搭建家庭媒体库 | 降低安装与配置门槛，完成首次播放和再次入库 | 无需自行申请、配置和维护识别服务 |
| 持续收片、追剧 | 自动监听、命名、分季、整理并交付媒体服务器 | 减少复杂命名和季集歧义造成的人工确认 |
| 集中整理历史收藏 | 批量预览、修正与整理 | 一次性处理大量难识别文件，适合按量包 |
| 熟悉自托管和 API 的用户 | 使用自己的配置完成整理 | 可按需选择官方服务，不强制转化 |

付费价值需要通过实际效果验证，包括首次配置耗时、无需人工介入的成功率、错误识别率和问题恢复成本。不能仅凭提供了模型调用就认定存在付费需求，也不承诺所有文件都能自动正确识别。

## 免费与付费边界

| 能力 | 规划边界 |
| --- | --- |
| 桌面安装、自托管部署、目录监听与扫描 | 免费 |
| 本地基础解析、用户自备元数据凭据、手动指定作品 | 免费 |
| 命名规则、批量整理、支持范围内的文件操作与媒体服务器交付 | 免费；具体支持范围按版本说明 |
| 预览、冲突阻断、人工纠错、失败恢复 | 免费，不以付费解锁文件操作保护 |
| 接入用户自己的识别服务 | 接入能力免费；仅承诺已支持的接口，第三方服务费用由用户自行承担 |
| 使用官方托管识别与整理 API | 付费，提供少量体验额度 |
| 本地状态展示、基础桌面通知 | 免费；现有本地能力不因新增托管服务而转为收费 |
| 官方托管消息投递、离线提醒、定期报告 | 第三阶段的付费候选能力 |
| 多设备配置同步等持续服务 | 根据需求另行验证，不作为首版承诺 |

官方额度耗尽或服务不可用时，用户仍可使用本地能力、自备服务或人工确认继续整理。不能把免费流程中的必要步骤改成官方付费服务专属。

## 三个推进阶段

### 阶段一：免费整理工具

**目标：让用户方便、放心地持续整理，建立内容入口和产品口碑。**

先交付免环境桌面安装、目录接入、基础识别、批量预览、人工纠错和可恢复入库。桌面运行能力与已实现的 Docker 功能应分别说明，不能把桌面规划写成现有能力。

运营围绕低成本家庭影院、网盘下载后的文件整理和播放连接，帮助用户完成第一部影片播放，再验证第二次新增文件能否持续入库。

进入下一阶段前，应有真实用户能够在无实时协助下完成首次设置，并在后续有新增文件时继续使用。观察配置放弃原因、人工确认与误识别情况，以及每位活跃用户需要的支持时间。具体门槛由内测基线确定。

### 阶段二：官方识别与整理 API

**目标：验证付费需求、实际识别效果和单位服务成本。**

提供免配置的官方 API，以复杂命名、别名消歧和季集识别为重点。先推出少量体验额度与简单按量包，避免同时上线复杂会员体系。免费流程与自备服务入口继续保留。

API 根据必要的名称上下文返回结构化识别结果或整理建议，文件路径与操作仍由本地程序校验和执行。付费识别结果同样需要经过作品、季集和目标冲突检查，低置信度结果保留人工确认。

运营展示真实案例的整理前后差异，明确哪些普通情况免费流程已足够、哪些困难情况适合官方服务。购买入口应展示预期消耗、剩余额度和计费结果，避免以模糊的“解锁整理”引导付费。

进入下一阶段前，需要验证真实付款、使用后的复购或持续需求、识别质量和贡献毛利。先分清一次性历史整理与持续新增需求，不能用首批大批量导入推算长期月用量。

### 阶段三：会员与持续服务

**目标：通过有持续价值的服务形成续费收入。**

会员可组合一定官方 API 额度、托管消息通知和定期报告；额外识别量可单独购买。偶尔整理的用户继续选择按量包，不强制转为订阅。多设备配置同步等能力根据需求另行规划。

| 消息类型 | 示例 | 交付条件 |
| --- | --- | --- |
| 整理与收录结果 | 一部电影或一季剧已入库 | 区分文件已整理与媒体服务器已收录 |
| 需要处理 | 识别不确定、目标冲突、空间不足 | 提供对应任务和可执行的处理入口 |
| 运行异常 | 媒体盘断连、Emby 不可达 | 依赖本地应用检测并上报，不承诺关机后继续检测 |
| 设备离线提醒 | 运行设备长时间未连接 | 需要云端心跳与离线判断，明确休眠和主动退出的处理方式 |
| 定期汇总 | 本周新增、待确认与失败任务 | 用户主动开启，提供频率与内容设置 |

通知按作品、目录或批次合并，避免每集发送一次。支持去重、投递重试与关闭通知；只在用户选定的渠道和频率下发送。各渠道的费用、接口限制和可用性确认后，再公布具体会员权益。

验证会员价值时，分别观察通知使用率、对实际问题的处理帮助、退订原因、续费率及服务成本；未读消息数量不能直接代表服务价值。

## 定价与计费策略

### 价格实验

以下仅作为实验候选，不是对外价格承诺。正式上线前需要结合模型、检索、元数据授权、服务运行和支持成本确定额度。

| 方案 | 候选价格 | 验证目的 |
| --- | --- | --- |
| 体验额度 | 少量免费额度 | 让用户用自己的真实文件验证效果 |
| 小额包 | ¥9.9 | 验证首次付费和偶发整理需求 |
| 批量包 | ¥29.9 | 验证历史收藏集中整理需求 |
| 年度会员 | 后续测试 ¥99/年 | 第三阶段验证 API 额度与持续服务的组合价值 |

第二阶段首版可只提供体验额度和一个小额包。额度、有效期、退款与扣费纠错规则应在购买前说明；不在成本未知时承诺无限识别、终身云服务或终身人工支持。

### 按识别工作计量

计费尽量贴近用户理解的作品识别工作。一部电影或一组同作品剧集可以作为一次识别单位的候选定义，不把每个视频文件、每次 HTTP 请求或每次内部模型调用直接当作收费次数。

- 同一任务的超时重试、幂等重放和已付费结果复用不重复扣费。
- 同一组剧集识别后，新增集能够可靠沿用作品结果时，不再次收取作品识别费用。
- 无法识别、服务异常和无有效结果不扣费；内部失败调用仍计入服务成本。
- 混合作品目录、超大批次和重新识别可能产生额外工作，需在执行前明确分组与预计消耗。
- 误识别提供反馈与额度纠错入口；有效结果的判定、复用边界和扣费流程在 API 方案中另行定义。

实现时需要账本、幂等标识和失败补偿，保证网络重试不会造成重复扣费。此处只确定计费原则，不把商业讨论直接扩展成当前桌面提案的实现任务。

### 成本与收入判断

按成功识别的计费单位核算成本，包含未收费的失败调用、重试、检索、元数据许可、基础设施、支付与退款，以及人工支持。缓存和同作品聚类可以降低成本，不能假设所有请求都能命中缓存。

分别跟踪每个付费用户的实际使用量与支持成本，以及每个成功识别单位的收入和可变成本。固定授权费用、产品维护和内容生产另行核算；套餐销售额、预付余额与已完成服务收入应分开观察，不直接视为利润。

软件授权销售、硬件佣金和陪同搭建服务不作为当前主收入假设。有真实合作或服务需求时再独立评估，避免分散免费工具与官方 API 的验证重点。

## 内容运营与转化

官网、账号简介与产品介绍统一使用「你的本地媒体库」作为产品 Slogan。具体家庭影院教程、选题与渠道分工沿用[产品定位与运营方向](./positioning.md)。优先使用小红书验证用户问题，以 B 站承载完整教程，官网文档提供可维护的配置与排障步骤。

转化路径：内容触达 → 跟随教程完成首次播放 → 免费工具完成持续整理 → 体验官方 API → 按需购买 → 在持续服务有价值时选择会员。

| 阶段 | 内容重点 | 用户下一步 |
| --- | --- | --- |
| 免费工具期 | 电脑加移动硬盘搭建、播放器连接、文件整理和排障 | 免费安装，完成首次与再次入库 |
| 官方 API 期 | 复杂命名与别名案例、整季识别、免费与官方服务的实际差异 | 用真实文件试用，再按需购买 |
| 会员服务期 | 入库通知、待处理提醒、异常发现与定期报告 | 主动开启需要的服务，评估是否值得续费 |

免费教程应能独立帮助用户完成流程。演示注明应用版本、设备条件和服务方式；如使用付费 API，明确说明。未上线的会员服务、通知渠道或识别效果不能作为现有卖点宣传。

基础指标区分教程访问、安装与配置、首次成功、再次入库、API 体验、首次付费、复购和续费。转化率使用相应阶段的用户作为分母；留存需区分有新增文件但未使用，以及期间没有新增文件。产品未具备统计能力前，以自愿反馈与跟访验证，不默认上传媒体清单。

Mac 内测的招募草稿、访谈提纲、分母及时间口径见[内测验证准备](./desktop-beta-validation.md)，逐人过程使用[首次入库记录模板](./desktop-beta-first-run.md)。这些是准备材料，实际发放以对应架构安装包验收为前提；维护者技术验证不计作独立用户成功。

## 服务与数据边界

免费本地流程不依赖官方账户和余额。用户主动选择官方 API 时，才发送完成识别必需的文件名及经裁剪的目录上下文；默认不上传视频内容、完整绝对路径、用户自备密钥或 Emby 凭据。服务启用前说明数据用途、保留周期和删除方式。跨用户缓存、共享纠错数据或训练用途不能从购买服务中推定授权。

官方云服务上线前应确认模型、检索与元数据服务的商用条件和费用。TMDB 官方区分商业与非商业使用，用户自备 Key 不代替产品商用安排判断，见 [TMDB 官方说明](https://developer.themoviedb.org/docs/faq)。项目现有 GPL-3.0 发行义务继续遵守；收费不等于自动获得将现有代码闭源的权利，见 [GNU 官方说明](https://www.gnu.org/licenses/gpl-faq.en.html)。

## 与当前实施计划的关系

当前本机桌面端提案（仓库路径：`openspec/changes/add-local-desktop-emby-ingestion/proposal.md`）服务于第一阶段：降低安装门槛，完成本地目录接入、可靠整理和 Emby 收录核对。该提案不实现账户、支付、官方识别 API 或托管通知。

后续分别为官方 API 和会员服务建立独立变更，再确定接口、计费账本、数据处理、通知渠道与验收标准。当前整理文档不启动收款、招募、消息发送或发布操作。

另已记录后续需求 REQ-15：面向没有 TMDB 账号或 API Key 的用户，由维护者后续提供元数据 API 服务，产品内置接入入口，降低首次配置门槛，同时保留自备 TMDB 凭据方式。具体接口、额度、费用及其与官方识别与整理 API 的关系待独立方案明确；当前不承诺免费、上线时间或纳入桌面端首版。

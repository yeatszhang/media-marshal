# Codex 指令作用域检查

本表验证从 Cursor 迁入后的导航和规则边界，不作为产品实施计划。指令变化时按相关场景复核。

| 场景 | 预期行为 |
| --- | --- |
| 修改 Electron 来源页面 | 从根 AGENTS 进入桌面开发与统一来源文档；不使用 Vue/Pinia 或 Java Controller 约定 |
| 修改 TypeScript Core 的下载功能 | 使用 contracts、IPC 与 Core 边界；旧文档“不做下载”不阻断已授权需求 |
| 追溯旧模板或季集行为 | 按需查迁移基线、旧 ADR/API 和源码测试，不全量加载旧日志，不把历史通过记录当成本轮验收 |
| 修复旧 Java 或 Vue 功能 | 应用对应目录 AGENTS，核对旧契约与实际代码；新证据记入对应变更，不继续追加冻结历史日志 |
| 修改 tools/desktop-parser | 按桌面 stdio 设计，不继承 parser/AGENTS 的 HTTP 接口要求 |
| 新界面处理字段、异步或批量失败 | 展示定位对象、可信原因和恢复动作；保留部分失败明细并验证异常路径，不泄露敏感信息 |
| 当前桌面仅要求中文 | 按变更范围交付，不受旧 Vue 全量双语要求影响 |
| 提交文档迁移且工作区已有代码改动 | 精确提交本轮文件或差异块，保留其他改动；文档构建、链接和范围校验通过后提交，不自动 push |

2026-10-25 迁移检查：六份历史正文仅调整元数据和链接，旧 Cursor 自动加载入口移除；根及旧工程指令均有明确作用域。文档构建和文件／链接检查用于验证迁移，不代表执行旧 Java、Vue、Python 或桌面业务验收。

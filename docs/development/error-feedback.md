# 错误与异常反馈（必须遵守）

- 所有报错、异常和操作拦截都必须在界面向用户说明具体原因，并给出明确反馈。覆盖前端校验、接口请求、后端处理、第三方服务、后台任务及批量操作，不得仅写日志、输出控制台、吞掉异常或只禁用按钮。
- 提示应说明哪个操作失败、哪个对象受影响、已知的具体原因，以及用户可以采取的下一步。不得只显示“操作失败”“发生异常”等笼统文案；原因尚不明确时如实说明，不得猜测，并提供可用的重试或诊断入口。
- 因校验或业务条件不满足而禁用操作时，必须在相关控件附近直接展示拦截原因。涉及文件、字段或条目时，应定位到具体对象，并在对应行或字段展示错误；不得让异常行继续显示正常或待核对状态。用户修正输入或排除冲突项后，提示与按钮状态必须实时更新。
- 重复或重叠季集号必须展示冲突文件名和实际冲突季集号或范围，并提示修正季集号或取消勾选重复文件，不能只提示“存在重复”。其他校验同样需要提供可定位的明细。
- 后台和异步任务的异常必须通过任务状态、详情或通知反馈到界面，并保留可查看的失败原因；不得仅依赖瞬时提示。批量操作必须说明成功与失败数量，并提供逐项失败原因，不得以整体成功提示掩盖部分失败。
- 后端必须通过响应、任务记录或事件保留并传递可展示的错误原因和关联对象，前端不得将已有具体原因覆盖为通用提示。技术堆栈与敏感信息不直接展示，诊断信息保留在日志中。
- 界面反馈统一使用所属工程现有组件和文案机制，语言覆盖范围遵循对应变更；旧 Vue 的双语要求不扩展为桌面本轮门槛。同一错误由统一拦截器或业务组件明确负责展示，避免重复弹出提示；统一处理不能替代字段级、逐项和持久化的错误明细。
- 新增或修改错误处理时，必须验证异常路径：用户能看到具体原因和受影响对象、知道下一步如何处理，且修正或重试后界面状态正确更新。不能仅验证成功路径。

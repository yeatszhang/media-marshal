# Media Marshal 项目路线图

> 本文件负责阶段顺序、优先级和进入条件。具体需求与验收条件见 [requirements-status.mdc](requirements-status.md)，设计结论见 [design-decisions.mdc](design-decisions.md)，落地证据见 [implementation-log.mdc](implementation-log.md)。

## 当前阶段（2026-09-05）

- 工作区版本：`v0.2.13.1`，包含未提交补丁；不代表远端已发行。
- 核心整理、Queue 批量编辑、已完成剧集批量修正及进度 / 失败重试已实现。
- 发行硬化尚未完成；任务管理和工程基础已有部分能力，不能按全新功能重复排期。
- 原路线图将 `v0.2.11` 作为未来版本已失效。后续按交付条件安排，具体版本在范围确定时分配，不回填或改写历史版本。

## 规划原则

1. 优先完成已有流程的可靠性、异常恢复、升级和外部试用闭环。
2. 区分代码完成、测试覆盖和发行验收，不用一个“完成”状态代替三者。
3. 后台文件作业与删除 / 重置 / 规则变更有一致的协调边界。
4. 任务历史不能直接充当长期资产索引；播放统计依赖资产索引。
5. 外部触发与鉴权、路径边界、审计一起设计；媒体清理晚于权限和恢复机制。
6. 保持媒体整理与维护工具定位，不扩展为下载器或播放器。
7. 从设计之初支持国际化，优先服务中国用户；新功能沿用语言资源机制，中国大陆网络可用性纳入相关交付验收，见 REQ-16。

## 阶段 A：当前版本发行硬化（未完成，最高优先）

关联需求：REQ-01、REQ-02、REQ-03、REQ-09 基础门禁。

本轮已校准文档状态、能力边界并补充部署 / FAQ。剩余工作：

- 核验固定版本镜像、Git tag / Release 与文档站实际发布情况。
- 验证现有迁移、停止写入后的完整备份、隔离恢复及配套回滚。
- 明确活跃作业期间删除任务、删除 / 修改规则、系统重置的后端约束。
- 接入已有后端测试、前端检查 / 构建、Parser 契约及文档 / 版本检查。
- 执行需求状态文档中的发行矩阵，记录未通过项和支持平台。

完成条件：新用户可按文档部署固定版本，旧用户可按已验证步骤升级 / 恢复；文件操作、并发冲突与失败恢复没有未解释的发行阻断项。仅修正文档、通过编译或拥有本地 tag 不满足条件。

## 阶段 B：任务管理与异常恢复（部分基础已实现，下一轮主开发）

关联需求及建议顺序：

1. **REQ-04 解析与重试治理**：防止确定性解析错误在每轮扫描中重复处理，提供可修复结果。
2. **REQ-05 作业检索与断线恢复**：补齐服务端查找入口，摆脱单一浏览器本地索引依赖。
3. **REQ-06 完整任务管理**：后端分页、历史详情和关联批次；保留 Dashboard 概览与 Queue 待确认职责。
4. **REQ-07 扫描作业**：可查询过程、计数、完成与中断状态。
5. **REQ-08 诊断与结果说明**：错误原因、配置来源、连通性、附属文件 / NFO 结果。

ADR-030 同季 / 同剧集修正核心已完成，不重复安排。Queue 跨页选择与批量确认是独立增强，不与后端跨页修正范围混淆。

完成条件：用户能定位全量任务、找回后台作业、理解错误与修复步骤；普通重试、重匹配、目标库修正和重新扫描语义明确。REQ-04/05 设计可与阶段 A 验证并行。

## 阶段 C：工程与数据治理（与 A / B 并行）

关联需求：REQ-02、REQ-09。

- 保留已有单项修正短事务和测试积累，补并发、重启、文件与数据库不一致的故障注入。
- 将现有显式迁移纳入统一版本 / 顺序管理；先保证可升级、可诊断，再选择工具。
- 为前端核心操作和 Parser 响应建立可重复测试，减少手工浏览器模拟依赖。
- 用代表性数据评估全量任务请求、大批次预览、SQLite 单连接等待及扫描开销。

完成条件：基础检查自动执行，结构变更有迁移与恢复证据，关键交互和异常可重复回归。前端主包拆分按实际性能安排。

## 阶段 D：独立资产索引与只读媒体库（候选中期方向）

关联需求：REQ-10。进入条件：历史、数据库升级与作业恢复边界稳定，形成独立资产模型 ADR。

- 定义资产身份、当前路径、媒体类型、TMDB、季集、来源规则、存在状态及历史关联。
- 先提供只读列表、搜索、详情、存在性核对和未知文件提示。
- 维护操作先有只读预览，并明确与整理任务的关系。

完成条件：能区分“历史任务成功过”和“当前资产仍存在”。本阶段不默认提供删除、批量移动、合并或孤儿文件清理。

## 阶段 E：播放统计与清理建议（候选长期方向）

关联需求：REQ-11。进入条件：阶段 D 稳定，资产与媒体服务器条目的映射规则明确。

- 优先评估 Emby，再根据需求安排 Jellyfin、Plex / Tautulli。
- 只读展示播放次数、最近播放、使用情况及清理候选原因。
- 明确路径映射、多版本资源、用户维度、同步失败 / 过期状态和最小化存储。

不自动删除、移动、归档。高风险操作另行设计权限、审计、二次确认及隔离 / 恢复机制。

## 按反馈决定的方向

- REQ-12：Webhook、认证、API Token，与外部触发安全模型一起推进。
- REQ-13：ISO、剧集蓝光、裸 BDMV、更多模板和附属格式，按代表性样本评估。
- REQ-14：邮件通知产品化，先明确启用与投递验证闭环。
- REQ-15：为无 TMDB 账号 / API Key 用户提供内置元数据 API 服务；待维护者提供接口后独立规划。
- SOCKS / 代理认证 / 海报代理、缓存管理、更多数据源按实际问题排期。

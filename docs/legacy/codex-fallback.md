# Codex CLI 识别兜底

> 旧 Java / Vue / Docker 工程资料，已于 2026-10-25 归档。下文的“当前”指原文核对时点，不代表桌面客户端能力。

自动流水线先用 GuessIt 解析文件名，再按路径和文件名特征将剧集聚类。启用 Codex 时，同簇只调用一次模型识别共同作品，每个文件分别回填明确的季集号，再经过 TMDB 与父目录增强校验。无法可靠聚类的文件继续沿用常规流程，仅在类型不明、没有候选或分数不足时调用单文件模型兜底。

模型接收文件名、最多四层父目录名、最多 80 个同目录视频文件名及原始解析字段。它不接收媒体内容或 TMDB Key，不操作媒体文件。CLI 使用隔离工作目录、只读沙盒，关闭 shell，开启受限联网检索，并忽略用户配置以免加载无关 MCP 或自定义提供商。

## 增量发现与调用成本

周期补扫首次建立目录索引，之后每轮只检查已知目录自身的修改时间和文件标识，发生变化的目录才重新枚举直接子项，只有新增路径进入识别流水线。深层目录分别检查，不依赖根目录时间；新目录会递归发现，忽略目录和蓝光原盘剪枝规则继续生效。文件内容修改不会重复识别已有路径。

自动发现通过数据库跳过所有已有路径，包括历史失败和已修正任务，避免重启后再次消耗 Codex 配额。目录索引保存在内存中，服务重启或规则热重载后重建；监听事件溢出时也会重建索引补漏。手动“全量扫描”仍枚举全部文件，并允许重试失败任务。目录修改时间不能可靠反映增删的文件系统，可用手动全量扫描核对。

按同一作品合并识别通常比逐文件分别调用更省 token：共同提示词、目录上下文、联网查证和作品身份只处理一次，明确的季集号本地解析，后续新增集优先复用已有身份缓存。不要把不同作品合并套用一个身份。当前已有同作品聚类缓存，因此 HTTP 请求次数不等于实际模型调用次数。

忽略模型缓存及检索开销，若共享上下文为 C、每文件输入为 F、文件数为 N，逐文件输入约为 N×(C+F)，一次批量输入约为 C+N×F；共同作品身份的输出也只需一份。该公式是估算，实际节省幅度需结合输入、缓存输入、输出及检索用量验证。[OpenAI Docs 的提示词缓存](https://developers.openai.com/api/docs/guides/prompt-caching)可复用相同前缀的计算，但仍会生成新的输出；本地身份缓存命中则直接省去模型调用。

## 本机桥接

需要 Python 3 与可用的 Codex CLI。使用官方 CLI 支持的 `exec --output-schema`、`--output-last-message` 和 `--sandbox read-only`，参考 [OpenAI Docs](https://learn.chatgpt.com/docs/developer-commands#codex-exec)。

通过 `python3 scripts/codex-bridge.py --config /path/to/bridge.json` 启动。配置文件权限应为 600，配置示例：

```json
{
  "runtime_dir": "/path/to/private/runtime",
  "codex_path": "/absolute/path/to/codex",
  "model": "gpt-6-luna",
  "web_search": "live",
  "host": "127.0.0.1",
  "port": 18081,
  "timeout_seconds": 150,
  "max_daily_calls": 10,
  "token": "替换为不少于32位的随机令牌"
}
```

直接复用本机 Codex CLI 保存的 ChatGPT 登录，固定 `model_provider="openai"` 和 `forced_login_method="chatgpt"`。先运行 `codex login status` 检查登录；未登录时运行 `codex login` 完成官方登录。`codex exec` 支持复用保存的登录并输出符合 JSON Schema 的结果，见 [OpenAI 官方非交互模式文档](https://learn.chatgpt.com/docs/non-interactive-mode)。

不再支持第三方 `provider` 配置，也不读取第三方 `.env`。旧配置中的 `provider` 会被忽略，升级本机服务时应移除该字段。子进程不继承 API Key 或服务端点覆盖环境变量；继续使用本机默认 `CODEX_HOME`（如已设置则沿用），不复制或输出登录凭据。消耗当前 ChatGPT 账号的 Codex 配额，模型需在该账号下可用；无需第三方余额或另配 API Key。

桥接提供 `GET /health` 以及带 `X-Media-Marshal-Token` 认证的 `POST /recognize`、`POST /recognize-cluster` 和 `POST /recognize-directory`。单文件及完整目录结果成功缓存 24 小时、未知缓存 5 分钟；共同作品身份成功缓存 30 天、未知或失败冷却 1 小时，避免同一簇逐集重复调用模型。单文件手动重试也优先复用已有作品身份。缓存键包含身份判定策略、Schema、模型和联网模式；仅压缩聚类输入输出时保留已有兼容身份缓存。CLI 调用串行执行，并设有排队和进程超时；失败响应不包含 CLI 原始输出。

`max_daily_calls` 默认 10，按上海时区自然日限制新模型进程启动次数。缓存命中不占额；失败也占额，重启不能重置计数，多个桥接实例通过事务共用上限。超限后停止新调用，保留人工指定作品和等待确认流程，次日恢复；主动重试不能绕过预算。官方提供商的 HTTP 和流重试均设为 0，避免一次任务在异常时反复重连。此处硬限制的是调用次数，单次实际 token 数仍有波动。

自动聚类仍在本地检查全部文件，但按季集坐标去重后只发送最多 6 个均匀分布的样本、目录名及文件数量摘要。模型只返回共同作品身份，不逐文件输出坐标，理由要求简短，提示最多两次针对性搜索；搜索次数是提示约束，调用次数由本地预算强制执行。保留 Luna、low 推理和 150 秒进程超时。

带同一认证头的 `GET /usage` 返回当日调用数、上限及 CLI 报告的输入、缓存输入和输出 token 汇总。数据保存在运行目录 `usage.db`，不保存提示词或凭据；从启用统计后开始累计。`input_tokens` 已含缓存输入，不能再加一次 `cached_input_tokens`。`reported_calls` 小于 `calls` 表示部分调用没有完整用量回执，未报告不代表零消耗。统计不用于推算账单金额。

自动聚类支持具名目录中的纯数字集号、合并集范围、`S02E03` 和动漫方括号集号。`01-8930371d37e8.mp4` 中的下载哈希会被剥离，同一集的多个副本仍归属同一作品；确认阶段继续检查重复集号。显式作品前缀不同的文件会拆成不同簇，纯数字文件则要求所在目录全部同质且有有效作品目录名。新簇至少需要两个不同的季集坐标；截断的目录列表、电影、原解析与文件名坐标冲突、泛目录中的纯数字文件均不自动聚类。

共同作品身份达到 0.6 置信度才缓存，并按监控规则、作品路径、文件名前缀和显式年份隔离。身份缓存不保存某一集的坐标：新增一集或旧集已移出目录时仍可复用，`S01`、`Season 02`、`第三季`、特别篇等同作品季目录也复用身份，各自回填季号；文件名明确季号优先于目录，缺省第一季。模型不会按文件排序生成集号。同簇身份仍需通过每个任务的置信度、TMDB 季集和目标路径校验；通过后自动整理。

## Media Marshal 配置

通过现有 `/api/settings/{key}` 配置接口保存：

| 键 | 含义 |
| --- | --- |
| `codex.enabled` | 是否启用，默认 false |
| `codex.bridge-url` | 桥接地址，Docker Desktop 默认 `http://host.docker.internal:18081` |
| `codex.bridge-token` | 与桥接相同的随机令牌，保存时设 `sensitive=true` |
| `codex.require-confirmation` | 已停用；历史保存值不再触发固定审批，改为按校验结果决定 |

前端“系统设置 → 识别配置”提供启用开关与作品匹配阈值。Codex 置信度至少 0.9，且 TMDB 匹配达到配置阈值后，才进入自动整理校验。部署前先在容器内验证桥接健康接口可达。

Codex 必须提供合法结构，结果为 `identified` 且置信度至少 0.6。原文件及目录中的明确季集号作为初始解析线索，季号还须结合元数据和完整集号范围验证；规则限定电影或剧集时拒绝不相符结果。模型建议必须再次经过 TMDB 搜索；单文件低分兜底不会降低已有候选的最佳分数。作品详情及最终季集号以 TMDB 默认季与分集列表为准，官网播出季数不直接覆盖 TMDB。缺少季集号的剧集仍需确认。

整理前统一校验 TMDB 季集存在性，覆盖自动整理、单条/批量确认及已完成任务修正。先检查来源季是否包含完整集号范围；来源季不存在或缺少其中任一集时，检查其他正片季的实际分集列表。只有一个季包含全部输入集号时，保留集号并采用该季号，映射提示记录两个坐标。作品及模型置信度、重复文件、目标路径等校验全部通过后可以自动整理，历史映射提示不会单独阻止重试。人工单条/批量确认遇到首次季号修正时仍先展示提示，再次确认后执行；修正流程在预览中展示目标路径与提示。特别篇不映射到正片，不猜测累计集号偏移，合并集逐集校验。多个季均可匹配、没有匹配、列表缺失或请求失败时暂停整理并说明原因；不能仅凭总集数或命名模板未使用 `{episode_title}` 而跳过分集验证。

咒术回战 case（[TMDB 95479](https://www.themoviedb.org/tv/95479)）：来源为 `咒术回战/S03/[BeanSub&FZSD][Jujutsu_Kaisen][48][GB][1080P][x264_AAC].mp4`，目录按播出分季，文件使用累计第 48 集。按用户确认的编号对应 TMDB `S01E48`；整理时须验证第一季实际存在第 48 集，不能直接相信路径 `S03`，也不能改成第三季首集 `E01` 或自行计算偏移。原始 `sourcePath` 保留，映射提示记录 `S03E48 → S01E48`，通过其余校验后自动整理。回归使用固定的季与分集夹具，运行时以 TMDB 实际接口返回为准。

模型判断多个数字时先区分语义，在可信集号候选之间通常优先保留较大的累计集号，再由后端校对元数据。年份、分辨率、编码及哈希不参与取最大值；较大编号也不能替代季与分集列表校验。

已有待确认任务可点击文件卡片顶部的“Codex 重新识别”，也可在“编辑识别信息”面板底部使用同名按钮。对应接口 `POST /api/queue/{id}/codex-rematch` 更新解析及 TMDB 候选，随后校验作品、季集、同目录重复文件和目标路径；通过后后台自动整理，以 `AUTO_MATCH` 标记来源。未通过的文件保留在队列并记录具体原因与识别依据。无法确定作品、TMDB 无候选或源文件不存在时，返回说明并保留原信息。

队列默认按同一监控规则及直接父目录分组、按目录分页。同目录多文件展示一份作品候选和季集表，按剧集聚类后整体识别，不再提供展开单文件详情入口。“批量识别并整理”先更新整目录识别信息，再检查季集重叠、TMDB 季集和目标路径。无冲突文件自动提交后台整理，仅为仍需处理的文件打开确认面板；缺少季号时自动补为第一季（路径明确标注其他季或特别篇时优先采用），也可统一修改，也支持逐文件修正、排除文件和失败项重试。重复或重叠的季集号会阻止提交。跨目录操作与手动搜索收纳在可展开的辅助区域。

目录摘要会保留部分文件已有的作品候选，并显示来源文件数（例如 1/13 个文件）。已有候选时可直接打开批量确认面板，由用户选择一个共同作品应用到全部勾选文件，不要求每个文件都先单独识别，也无需再次调用 Codex。共同候选优先展示；多个不同候选需要用户明确选择，部分文件来源的候选会显示复用范围说明。各文件原有季集号保留，重复或重叠集号仍需修正或排除，后端继续通过 TMDB 校验。仅整组完全没有候选或候选加载、识别、提交期间禁用批量确认，并在卡片与按钮处提示原因。识别依据集中在目录层展示，文件表中明确显示可沿用整组作品的状态。

目录卡片的“批量识别”（单文件详情中为“Codex 识别同目录”）会收集**同一监控规则、同一直接父目录**中的待确认普通视频任务，通过 `POST /api/queue/{id}/codex-directory-rematch` 一次调用桥接的 `/recognize-directory`。模型根据父目录层级和同目录视频文件名判断电影或剧集，返回共同作品身份及逐文件的季、集、合并集范围。通过一次作品级 TMDB 检索后，候选分发给各任务，保留已有明确季集号；整目录完成校验后自动提交无冲突文件到后台整理；重复或重叠季集号的双方、低置信度和元数据冲突保留人工处理，允许继续使用“批量确认”。

目录混有不同作品、存在无法归属的文件或缺少可靠身份依据时，模型应返回 `unknown`，保留原信息。多视频目录不能批量套用电影身份。目录内最多 80 个视频，超出时提示拆分；缺少季号时默认第一季，优先保留明确的季号、目录中的 S02 / 第二季等标记及第 0 季特别篇。已完成或处理中任务不参与，源文件消失或调用期间状态发生变化的任务会跳过。此入口不递归处理子目录，不创建尚未扫描入库的任务；跨季目录应分别在对应子目录执行。完整目录结果缓存 24 小时；列表变化后，若全部请求文件属于已有可靠作品簇，则直接复用身份并解析各自坐标，否则重新调用模型。手动整目录识别成功后也会为可靠同质簇建立身份缓存，供后续新增文件使用。

模型使用 `gpt-6-luna`、low 推理强度，通过官方 Codex CLI 原生联网检索查证错字、谐音和别名；找到可靠证据后返回正式片名及来源 URL。示例：“尼古猫猫”经作品官网查证可对应《ヤニねこ》，随后使用正式片名搜索 TMDB，不再把 `01.mkv` 作为作品名追加查询。队列卡片展示识别依据，无需新增搜索服务密钥。

仍然无法消歧、搜索失败或完全没有作品线索时返回 `unknown`。模型不能读取视频内容；用户仍可补充正式片名或手动指定作品。

## 验证

```sh
cd backend && mvn test
python3 -m unittest discover -s scripts -p test_codex_bridge.py
cd frontend && npm run test:queue && npm run build
```

桥接回归覆盖真实的 19 文件目录（13 集及 6 个哈希副本）、并发只调用一次、新增单集、跨季与重启复用、规则/路径/年份隔离、混合作品拆簇、合并集、中文季号、未知和异常结果的短期缓存、缓存过期及损坏恢复。后端用真实 HTTP 客户端验证聚类协议与坐标边界，并验证流水线先应用共同身份、不重复单文件兜底、TMDB 无候选时保留源文件等待确认。

CLI 进程回归验证官方提供商和 ChatGPT 登录参数、只读权限、目录结构化输出、环境变量过滤、忽略遗留第三方配置、失败时不泄露进程输出，以及请求临时文件清理。认证方式包含在缓存策略中，切换后不会沿用第三方调用失败产生的短期缓存。另有并发占额、重启保留预算、上海时区跨日恢复、失败占额、超限 HTTP 429、用量鉴权与缺失回执、耗尽预算仍可读缓存，以及 30 天身份缓存与 1 小时冷却等回归。

确认整理前，前后端都检查剧集季号和集号是否完整，单条及批量确认均无法绕过；未标注季号时默认第一季，明确的其他季及特别篇保持原值；缺少集号时引导编辑，防止目标路径残留模板占位符。外置盘监控根目录不可访问时暂停缺失检测，避免把暂时的挂载错误当作源文件删除。


自动整理在任何文件操作前检查整批目标，既检查库中已有目标，也检查同批文件是否渲染到同一路径。重复检查覆盖同目录尚未入队的数字集号、`SxxExx`、动漫方括号集号及下载哈希副本，不会先任选一个副本移动。目标路径含未填充模板变量或不安全路径时同样暂停。后台整理返回 `PROCESSING`，最终完成或失败仍通过任务状态和 WebSocket 展示；接口响应中的待确认文件带具体原因，不能将“候选更新成功”解释为全部整理成功。

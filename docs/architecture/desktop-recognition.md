# 桌面识别基础

独立同步、识别映射与 Emby 路径关联的验证范围及复现入口见[独立流水线验收](../development/independent-pipeline-validation.md)。

## 独立规则与文件计划

桌面从「识别与映射」添加规则：选择已有普通目录或已授权的受管下载根，按电影／剧集添加目标目录与命名模板，保存草稿、查看完整配置范围后再确认启用。可暂不填目标，先发现和识别文件；此时 COPY 等待补齐映射。默认输入在确认时绑定，更改设置中的默认目录不会改已有规则，编辑时须明确勾选重新绑定。

「查看接入与任务」显示当前输入的候选及原因，「补扫此识别输入」提交可查询的后台作业。普通输入至少连续观察 120 秒，受管输入只认正式成功收据。到「待处理」核对作品、季集和命名；唯一同类目标自动匹配，多个同类目标须逐文件明确选择，批量编辑也逐项保存选择。文件预览绑定当前规则和 Emby 关联，配置变化后重新预览。任务与配置预览链接可以重载查询，查询不重新提交 COPY。

自动策略先保存并确认规则版本，再从真实文件预览进入首次样本授权。必须明确勾选已核对作品、季集、目标、命名和策略局限；仅打开页面或选择自动开关不会授权。修改版本后需重新授权。普通下载客户端尚未满足完整行为矩阵时继续人工确认。

暂停来源同步、暂停单个识别规则与暂停全部识别整理分别控制。恢复一个规则不会解除全局暂停。删除须先暂停并等待活动文件步骤结束，保留输入、媒体和历史，恢复后仍暂停。已受理 COPY 的手动重试与后台恢复共用冻结计划：即使当前规则已换输入或目标，仍核对原卷、原文件并写原目标；尚未开始的复制重新连续观察，已校验暂存及已提交成果不要求下载输入在线。

独立识别规则选择普通目录或受管下载根。普通目录直接接入，不要求同步来源和额外复制；受管输入只枚举不可变成功收据，完成通知与补扫共用接收入口，逐项核对原卷、文件身份与摘要。同步收据本身是持久完成事实，`recognition_receipt` 记录接收及不可用原因，重复通知和补扫复用唯一候选。未配置识别不阻断同步；成果缺失不反向补传，暂存、外部放入文件和额外硬链接不作为可信完成成果。受管输入不开放普通目录的全量内容复核入口，以免把外部文件伪造为正式成果。

规则可以暂不配置 target，先发现并识别已有视频。电影和普通剧集分别匹配目标；唯一匹配自动生成命名计划，同类多个或缺目标等待人工选择。每个逻辑 target 保存类型、目录身份和模板；更换目录或类型时使用新 target ID，原 ID 保留给历史任务与交付。名称和模板调整仍追加规则版本。Emby 以逻辑 target 关联库根，同一本机目录下不同类型的目标可分别关联，COPY 不依赖 Emby。

未确认文件预览核对规则版本、默认设置代际、目录和 Emby 关联。已受理 COPY 冻结输入、媒体目标、路径、内容证据、逻辑 target 和绑定；规则编辑不替换原文件计划。接管旧输入前等待当前文件步骤安全点，旧版本、候选和收据保留；追加 schema v33 允许输入不绑定单一媒体目标，不把输入目录冒充输出目标。暂停识别只协调该规则和文件步骤，恢复不解除全局暂停；来源同步对已完成成果的处理独立。

自动策略必须核对当前规则版本的首次样本预览并明确授权。成功成果、唯一高置信作品和真实季集均须通过；普通客户端没有完整行为证据时继续人工。修改规则版本后重新授权，暂停后保留意图，恢复时重新观察并核对当前预览。已有作品查询计划、父目录约束、真实分集、命名和安全修正沿用原实现。修正计划保留有效逻辑目标和独立交付关联，不重新读取下载原件。


领域规则位于 `packages/media-core/src/domain/`，不依赖 Electron、文件系统或 DI。固定夹具覆盖模板、查询计划、评分、季集与修正范围，每项保留 Java 方法引用及来源摘要；输入和期望人工对照旧测试／实现，新规格修正的差异另记。运行 `npm run test:rules` 无需 Java、旧服务或数据库；夹具和证据边界见[行为对照基线](./desktop-migration.md#固定行为夹具)。

归一化拒绝小数集号、错误字段类型和非连续范围；季号线索从最近名称向上查找五层。TMDB 季集校验检查实际分集集合，不以集数总量代替存在性，不按累计集号猜偏移。只有唯一其他正片季包含全部集号时才换季；特别篇不换成正片，任一必要列表请求失败均保持未确认。重复/重叠坐标由共享函数检查，自动、人工和修正用例须复用。

查询计划保留本地化、原语言、双语和 guessit 的顺序及权重；全年份搜索无结果时去掉年份重试，续季不按首播年份过滤。父目录只接受带明确发行线索且季号一致的目录。相同作品 ID 且文件名、父目录置信度均不低于 0.60 才能相互加分；单独父目录或只有弱文件名证据时，上限不超过 0.75 和自动阈值减 0.01。这里按新规格收紧旧实现中“只要同 ID 就加分”的行为，不能依此绕过人工确认。

TMDB 适配器实现集中请求、超时和取消，仅它显式使用已配置代理，Emby 的 HTTP 客户端不读取环境代理。请求合并按调用者计数，一个页面取消不影响其他调用者；无人等待或适配器关闭才终止底层请求。响应最多 8 MiB，不跟随重定向；错误、未知结构、错误作品身份及不可靠季列表不写成功缓存。内存缓存最多 256 条且总量 32 MiB；SQLite 最多 1000 个 256 KiB 成功条目，大响应仅用于本次请求。缓存键不含凭据，凭据仅通过受限宿主通道在内存配置。

接口依据：[TMDB 电影搜索](https://developer.themoviedb.org/reference/search-movie)、[剧集搜索](https://developer.themoviedb.org/reference/search-tv)与[分季详情](https://developer.themoviedb.org/reference/tv-season-details)。

Core 的 `IngestionPipeline` 已接入这些规则：候选进入持久化任务后异步解析和搜索，结果、分值及证据写入候选表；编辑草稿不会整理，显式保存识别信息仅更新识别字段，整理预览重新请求作品详情和真实分集。新来源默认人工确认；显式完成首次预览授权后，自动意图才可推进有可靠完成证据的新候选，不按分数直接跳过预览或 COPY 核验。父目录补充分值不能免去逐文件和季集核验。解析或网络失败保留待确认任务，修复配置后显式重试，不将失败缓存为已识别。

识别失败按固定消息区分 TMDB 密钥／权限、限流、网络或代理、超时、无效响应、解析器不可用和文件／配置变化。未知异常使用通用提示，不保存或回显原始错误、URL、请求头或密钥。修复后重试沿用同一任务与候选，识别本身不创建 COPY 操作。核心重启会重新开始稳定观察，不能将重启期间的时间累计为已稳定。

`ingestion.preview` 生成十分钟有效的不可变计划，绑定来源版本、文件快照、连接版本与电影/剧集目标路由；确认时重验。`ingestion.confirm` 以请求键和候选唯一约束创建持久操作，重复确认复用原操作。COPY、提交及 Emby 交付的实现和验收边界见[桌面整理流水线](./desktop-ingestion.md)。

## 候选季集预检与共享校验

`validateMediaSelection` 统一读取作品详情、核对真实分集、唯一换季和现有坐标占用，供后台识别预检、人工整理预览及修正预览调用。特别篇只核对 S0，连续合并集必须逐集存在；需要比较的任一季请求失败，不能按剩余成功响应推断唯一季号。换季不改绝对集号或合并范围，完成后再按实际作品与季集核对已有 COPY／修正占用。文件执行前原有版本、来源和坐标重验继续保留。

后台识别只预检排名首个候选，整体最多十五秒，超时取消请求并保留待核对匹配；同分按媒体类型及 TMDB ID 排序，持久读取沿用相同顺序。校验结果作为该候选的可选 `episodeCheck` 证据保存，不修改原始解析季号、分数或其他作品。界面显示真实坐标及是否唯一换季，失败显示受控原因并保留作品匹配；未预检和旧候选明确提示在整理预览时核对。预检通过只说明当时的季集与占用证据，不授权整理，也不替代后续预览重新读取元数据和确认。

分集请求沿用来源任务的取消信号；来源暂停、规则变化或停止后，迟到结果不能写入候选。取消在共享校验出口重新检查，不能被分集错误归类吞掉。人工及修正预览继续使用自己的生命周期与版本检查。

`episodeCheck` 沿用既有候选 JSON，公共契约校验状态与坐标，旧候选仍可读取。单独预检阶段没有增加数据库表，也未完成自动执行入口；后续 schema v27 的持久自动意图见下节，不能把候选预检本身等同于自动整理授权。

## 自动整理意图与共享季集校验

新来源默认逐项确认。用户先按当前范围与目标生成真实人工 COPY 预览，再在来源编辑中选择自动策略；配置预览展示冻结样例的作品、来源文件、实际目标和大小，须明确勾选条件与局限后提交。`source-rules.apply` 只接收样例引用与 `accepted: true`，Main 原生授权和 Core 复核继续执行。首份样例必须可归属到该来源，自动流程自己的预览不能用于首次授权；授权与来源版本在同一个 SQLite 事务落库。保存草稿、切换开关、读取或重载均不替用户接受。

schema v27 的 `source_automatic_consent` 绑定来源、范围、媒体路由和授权根身份；名称与周期变化不改变已接受范围，卷身份、输入、目标、媒体类型或筛选／忽略范围变化需重新核对。未填写和 `null` 都表示默认本地忽略，显式空列表仍表示关闭可配置忽略，二者不混淆。原卷重挂载忽略临时设备编号变化，仍保留卷身份和根 inode／birthtime 约束。旧 `desktop_source.automatic=0` 列与旧保存接口继续保留人工模式；统一来源有效版本是自动策略的权威，来源 DTO 和运行模式按它投影。

`AutomaticIngestion` 由 `IngestionPipeline` 持有，和手动操作共用识别、`validateMediaSelection`、预览与确认入口。它只领取未被人工领取的新候选，先核对正式受管完成记录、原文件身份与摘要、写入者停止、至少 120 秒稳定观察及首次授权。当前本地客户端完整行为矩阵仍未满足，没有可自动放行的本地配置；夸克、自定义及历史其他标签均记录具体人工原因，不能仅凭稳定大小通过。共享来源的自动权限产品规则仍待选择，多个有效来源当前转人工，不能据此缩小最终需求或完成 7.3。

识别沿用 80% 阈值；达到阈值的不同作品必须唯一，父目录独有证据、人工编辑、过时匹配和不完整季集均转人工。剧集预检只是首项证据，自动预览仍重新获取真实分集并执行唯一季映射和现有坐标占用核验，与人工及修正使用同一函数；高分不能替代缺集、特殊集与跨季歧义判断。

| 自动阶段 | 持久事实与恢复边界 |
| --- | --- |
| PENDING | 候选、逻辑来源及冻结上下文，固定识别／预览／确认请求键 |
| RECOGNIZING | 与任务领取同事务写入原任务 ID；人工先领取时转人工，不接管其任务 |
| PREVIEWING | 已选作品与季集，调用原逐文件预览；元数据、路径、容量或分集失败转人工 |
| CONFIRMING | 冻结预览 ID；确认事务内再次核对自动授权、来源和文件版本 |
| SUBMITTED | 原文件操作 ID；重复调度只读原收据，COPY 与 Emby 沿既有所有者推进 |
| NEEDS_REVIEW | 持久失败原因；不自动重试或把原意图改用新来源策略 |

暂停、缺盘、成果恢复核验或重启时保留当前阶段与等待原因，恢复后重新观察；恢复核验明确失败时转人工，不能把已终止核验显示为仍在等待。来源版本／生命周期或文件版本变化则转人工。来源暂停和停止信号进入自动预览的元数据请求，异步返回后及确认事务内均重查授权。停止等待排空真实在途步骤；确认已提交但自动回执丢失时先读原操作收据，即使配置已变也保留既有计划，不能重复登记 COPY。人工保存识别字段后仍须人工预览确认，不由旧自动意图继续执行。

## 人工识别字段与重新匹配

schema v18 保存人工识别字段、编辑版本、已匹配版本及幂等收据。待处理中的单条入口和任务勾选共用 `ingestion.preview-recognition-edit` 与 `ingestion.save-recognition-edit`。一次最多 100 项；Renderer 按最多 8 项并发读取任务，为 Core 的 64 个等待请求名额保留空间。命令只接受任务 ID、预期识别版本和受限字段，不接受路径、凭据、任意文件动作或自动整理开关。

只修改勾选的标题、年份、媒体类型及季集，其余按每个任务的原值保留。改成电影会清除季集。剧集可保留各自集号，或按自然文件名正序／倒序生成单集号；合并多集不参与顺序生成，不能同时指定直接集号与顺序生成。缺失季集及同标题、年份、季号下的重复／重叠范围逐项显示文件名、实际 S/E 范围和修复动作。不同作品的最终身份与跨任务坐标仍由后续 TMDB 整理预览核验。跨目录选择显示额外说明，目录摘要不代替整组确认。

预览只读。保存在一个短事务中重新计算指纹，核对任务状态、候选、来源、生命周期及识别版本；任一成员改变都要求重新预览，整批字段更新不会半成半败。重复请求返回原收据，不重复加版本或重新排队。已有 COPY 或已完成任务不能通过识别编辑更改，应使用后续修正入口。字段草稿保存在组件状态，StrictMode 和重载只读取，用户改字段立即使界面预览失效。

「仅保存识别信息」保留原 TMDB 候选并标记待重新匹配。「保存并重新匹配」将原任务排队，不等待网络、不创建新任务或 COPY。重新匹配使用人工标题，避免原文件名再次盖过编辑；结果明确标为人工识别字段，不冒充文件名或父目录证据。网络、认证或解析失败保留人工字段及逐项失败原因，重试沿用同一任务。暂停、缺盘、重启仍遵守原稳定观察和调度边界。

整理预览绑定识别版本。保存字段使未确认预览过期；整理预览生成结束及确认事务内再次检查版本，因此异步目录／容量等待期间的编辑也不能让旧确认继续提交。保存本身不写媒体；后续整理预览仍按真实 TMDB 分集、来源快照、路径和容量逐项核验。

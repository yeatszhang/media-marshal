# 桌面识别基础

领域规则位于 `packages/media-core/src/domain/`，不依赖 Electron、文件系统或 DI。模板夹具按旧 Java 测试方法名维护，查询计划覆盖双语标题、字幕组、纯元数据、数字作品名和连续集。运行 `npm test -- packages/media-core/src/domain` 无需 Java。

归一化拒绝小数集号、错误字段类型和非连续范围；季号线索从最近名称向上查找五层。TMDB 季集校验检查实际分集集合，不以集数总量代替存在性，不按累计集号猜偏移。只有唯一其他正片季包含全部集号时才换季；特别篇不换成正片，任一必要列表请求失败均保持未确认。重复/重叠坐标由共享函数检查，自动、人工和修正用例须复用。

查询计划保留本地化、原语言、双语和 guessit 的顺序及权重；全年份搜索无结果时去掉年份重试，续季不按首播年份过滤。父目录只接受带明确发行线索且季号一致的目录。相同作品 ID 且文件名、父目录置信度均不低于 0.60 才能相互加分；单独父目录或只有弱文件名证据时，上限不超过 0.75 和自动阈值减 0.01。这里按新规格收紧旧实现中“只要同 ID 就加分”的行为，不能依此绕过人工确认。

TMDB 适配器实现集中请求、超时和取消，仅它显式使用已配置代理，Emby 的 HTTP 客户端不读取环境代理。请求合并按调用者计数，一个页面取消不影响其他调用者；无人等待或适配器关闭才终止底层请求。响应最多 8 MiB，不跟随重定向；错误、未知结构、错误作品身份及不可靠季列表不写成功缓存。内存缓存最多 256 条且总量 32 MiB；SQLite 最多 1000 个 256 KiB 成功条目，大响应仅用于本次请求。缓存键不含凭据，凭据仅通过受限宿主通道在内存配置。

接口依据：[TMDB 电影搜索](https://developer.themoviedb.org/reference/search-movie)、[剧集搜索](https://developer.themoviedb.org/reference/search-tv)与[分季详情](https://developer.themoviedb.org/reference/tv-season-details)。

Core 的 `IngestionPipeline` 已接入这些规则：候选进入持久化任务后异步解析和搜索，结果、分值及证据写入候选表；人工编辑只修改页面草稿，预览重新请求作品详情和真实分集。所有来源当前均要求人工确认，不按置信度直接执行 COPY。父目录补充分值不能免去逐文件和季集核验。解析或网络失败保留待确认任务，修复配置后显式重试，不将失败缓存为已识别。

识别失败按固定消息区分 TMDB 密钥／权限、限流、网络或代理、超时、无效响应、解析器不可用和文件／配置变化。未知异常使用通用提示，不保存或回显原始错误、URL、请求头或密钥。修复后重试沿用同一任务与候选，识别本身不创建 COPY 操作。核心重启会重新开始稳定观察，不能将重启期间的时间累计为已稳定。

`ingestion.preview` 生成十分钟有效的不可变计划，绑定来源版本、文件快照、连接版本与电影/剧集目标路由；确认时重验。`ingestion.confirm` 以请求键和候选唯一约束创建持久操作，重复确认复用原操作。COPY、提交及 Emby 交付的实现和验收边界见[桌面整理流水线](./desktop-ingestion.md)。

## 人工识别字段与重新匹配

schema v18 保存人工识别字段、编辑版本、已匹配版本及幂等收据。待处理中的单条入口和任务勾选共用 `ingestion.preview-recognition-edit` 与 `ingestion.save-recognition-edit`。一次最多 100 项；Renderer 按最多 8 项并发读取任务，为 Core 的 64 个等待请求名额保留空间。命令只接受任务 ID、预期识别版本和受限字段，不接受路径、凭据、任意文件动作或自动整理开关。

只修改勾选的标题、年份、媒体类型及季集，其余按每个任务的原值保留。改成电影会清除季集。剧集可保留各自集号，或按自然文件名正序／倒序生成单集号；合并多集不参与顺序生成，不能同时指定直接集号与顺序生成。缺失季集及同标题、年份、季号下的重复／重叠范围逐项显示文件名、实际 S/E 范围和修复动作。不同作品的最终身份与跨任务坐标仍由后续 TMDB 整理预览核验。跨目录选择显示额外说明，目录摘要不代替整组确认。

预览只读。保存在一个短事务中重新计算指纹，核对任务状态、候选、来源、生命周期及识别版本；任一成员改变都要求重新预览，整批字段更新不会半成半败。重复请求返回原收据，不重复加版本或重新排队。已有 COPY 或已完成任务不能通过识别编辑更改，应使用后续修正入口。字段草稿保存在组件状态，StrictMode 和重载只读取，用户改字段立即使界面预览失效。

「仅保存识别信息」保留原 TMDB 候选并标记待重新匹配。「保存并重新匹配」将原任务排队，不等待网络、不创建新任务或 COPY。重新匹配使用人工标题，避免原文件名再次盖过编辑；结果明确标为人工识别字段，不冒充文件名或父目录证据。网络、认证或解析失败保留人工字段及逐项失败原因，重试沿用同一任务。暂停、缺盘、重启仍遵守原稳定观察和调度边界。

整理预览绑定识别版本。保存字段使未确认预览过期；整理预览生成结束及确认事务内再次检查版本，因此异步目录／容量等待期间的编辑也不能让旧确认继续提交。保存本身不写媒体；后续整理预览仍按真实 TMDB 分集、来源快照、路径和容量逐项核验。

隔离真实文件测试覆盖字段保存不复制、原候选标记、人工标题重匹配、认证失败与原任务重试、旧预览和异步确认失效。真实 Electron 开发构建验证批量字段预览、自然顺序、保存、窗口重载及 Core 重启，原视频和空目标目录保持。这是第 3.7 项字段编辑阶段的证据；后续目录与跨项确认见下文。

复现：`npm test -- packages/media-core/src/ingestion/recognition-edits.test.ts packages/media-core/src/ingestion/pipeline.test.ts apps/desktop/src/renderer/src/recognition-edits.test.tsx`；构建后运行 `npm run test:desktop -- --grep '识别字段通过真实 IPC'`。

## 目录分组与持久批量识别

待处理页支持文件／目录两种视图。Core 从已登记的当前候选计算目录，按物理来源、父目录和整理策略分开，不用任意请求路径遍历文件系统。目录列表每页 25 组、成员每页 100 项，摘要和总数跨成员分页计算；本页勾选不隐含选择整组。已完成、已替代及不支持资产不参与待处理分组，不可访问的普通视频保留原因和记录。

目录候选汇总按 TMDB 类型与作品 ID 计算逐文件支持数，识别字段已编辑但未重新匹配的旧候选不提供支持。只有整组每个文件都有当前候选且处于待确认状态时才标为共同候选；部分支持明确显示 N/M，缺少识别或远端失败不能冒充共同结果。即便存在共同候选，也只作为人工参考，不创建整理预览或 COPY。

`ingestion.directories` 和 `ingestion.directory` 只读取已登记候选，目录引用绑定来源、父目录及策略；跨来源或错误引用被拒绝。`ingestion.recognize-batch` 一次最多明确选择 100 个候选，立即返回持久批次 ID。schema v19 在同一事务保存批次、原候选、来源版本、生命周期、策略及每项稳定请求键。相同请求重用原批次，重复或并发批次仍沿候选唯一领取复用原任务。

批次每轮最多提交 4 项，未就绪、暂停、缺盘、目录授权恢复或内容复核时持久等待，不能跳过稳定观察。等待项延迟再查，避免前一批离线文件堵住后续可运行批次。规则或资产版本变化要求按当前来源重新选择；已删除来源不接受新的潜伏意图。跨 Core 重启继续原批次，任务已创建而批次尚未补记时关联原任务，不重复解析或创建任务。

提交识别、匹配完成和文件整理是不同阶段。批次分别显示待提交、已提交、提交失败与匹配需处理数量，逐项保留原任务 ID、等待和失败原因，提供定位入口。匹配失败仍沿待确认任务重试。`ingestion.cancel-recognition-batch` 只停止后续提交；等待期间已经提交的任务仍记录并保留，不解释为撤销文件。React 轮询和窗口重载只查询，不重放批量命令。

隔离 SQLite 测试覆盖幂等、跨批次领取、等待公平性、逐项失败、取消、补记故障及数据库重开；真实文件测试覆盖暂停恢复后的重新观察、规则改变和没有 COPY。目录分组与逐项识别提交已接入界面；共同作品与跨项整理确认见下文。

## 共同作品与逐文件批量整理

目录摘要可把所选候选的 TMDB ID 和媒体类型填入本页已勾选的待确认任务草稿。部分文件支持的候选仍明确显示支持数量，选择它表示用户本次指定作品，不会把摘要升级为已核实结果。文件视图也可从最多 100 个明确勾选的任务打开草稿。每个文件保留自己的季集，可修改或取消选择；共同 ID、模板、附属文件选项均只在本地草稿中变化，不修改已保存的识别字段，也不操作媒体。

schema v20 新增持久批量整理预览、成员及确认收据。`ingestion.preview-organize-batch` 只接受已有任务 ID、预期识别版本、作品选择和受限模板／附属文件选项，立即返回批次 ID。原单文件预览逐项取得真实作品、分季和分集信息，检查来源稳定性、原卷、目录权限、目标、容量和附属文件。十分钟有效期从批次创建计算，分页和轮询不能延长。原计划请求键在成员中固定，回执丢失和 Core 重启继续同一预览。

预览完成后，按实际映射后的季集检查全批重复／重叠；错误给出双方文件名、实际 S/E 范围和修改／取消动作。主文件和附属文件的完整目标、文件／目录前缀、卷上的大小写及 Unicode 等价冲突一起检查。每项最多保留 20 条有界原因，任一项阻断都不能确认有效子集。预览结束和确认事务再次核对成员、资产版本、来源生命周期、策略、授权、连接和识别版本，变更后须新预览。

`ingestion.confirm-organize-batch` 必须携带显式 `filesComplete: true`，对应用户确认文件完整且核对全部计划的操作。确认只持久保存整批意图，之后每轮最多提交 4 项原 COPY 计划；已确认并不代表全部文件同时成功。原单文件确认不能领取属于批次的预览，包括预览已保存但成员回执尚未补记的窗口。确认后外部目标抢占或资产变化按项记录失败，其余项继续，不能回滚已发布文件。

同一确认标识、重复点击、窗口重载与 Core 重启复用原操作。操作已领取而批次补记失败时，只按原预览的操作收据补记，即便观察、成员状态或预览有效期随后改变，也不再新建 COPY。未领取项在暂停、缺盘或授权未恢复时持久等待，恢复后重新连续观察至少 120 秒；预览到期或配置变化则保留逐项原因并要求重新选择。原连接证据无法延续时，尚未领取的成员要求重新预览；已领取成员仍只按原操作收据补记。停止批次仅阻止后续预览／提交，已经开始或提交的项继续保存记录和文件。核心退出不会在异步目录等待之后领取新预览；在途网络取消保留未完成意图供重启继续。预览或确认期间发生暂停也保留等待状态，恢复后沿原请求核对，不把暂时暂停写成永久失败。

批次列表和成员详情均按 25 项分页，成员摘要只给附属文件数量，完整附属路径按需单项查询（最多 100 项），避免一批附件造成超限消息。界面区分已预览、阻断、已提交、文件完成与失败数量，并提供原任务定位；附属文件失败也计入需处理，Emby 交付继续独立记账。StrictMode、轮询、重载只查询，失败重试沿原请求标识，不自动确认。打开新整理草稿会清除历史批次的完整确认勾选，并提示先生成新预览或关闭草稿，避免误提交仍在界面中的旧计划。

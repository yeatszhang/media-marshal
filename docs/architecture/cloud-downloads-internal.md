公开 DTO 从 `@media-marshal/contracts` 导入；Provider、Engine 和宿主消息从 `@media-marshal/contracts/internal` 导入，RPC 实现从其 `/rpc` 子入口导入。Renderer 和 Preload 的内部导入、公开契约重导出内部协议均由依赖检查拒绝。

公开命令只接受应用 UUID 和业务选项。远端定位、组件路径、临时 URL 与授权不作为公开命令参数。`CloudDriveProvider` 管理认证、目录、元数据和传输租约；`TransferEngine` 消费租约并提供执行观测。当前租约仅定义只读回环 WebDAV，新增传输方式需扩展内部联合类型和双方能力，不改用任意 URL 兜底。

Core 是业务状态所有者，Main 是权限及生命周期入口，Host 执行基础设施动作。反向通道由 `RestrictedHostClient → RestrictedHostRelay → RestrictedHostServer` 组成，使用两个私有端口。按需宿主、资源预检和受管 OpenList 保留原三目标验收；新增生产 Provider、Rclone 调度与下载界面以 Mac 为当前验证范围。

每个请求携带核心、Host、绑定三种代际，以及 attempt UUID 和幂等键。Main 和 Host 都核对当前授权；输入中的绑定与 attempt 必须匹配上下文。长传输的 start 返回执行句柄，执行状态独立查询。进度序号只在同一个执行和同一代际中递增，重复、乱序与旧代际事件被丢弃。进程退出只提供核对证据，不能直接发布文件或写入业务完成状态。

Host 对写操作保留当前代际的执行收据，重复键或同 attempt 的重复启动共用同一次执行。输入变化产生冲突；收据满额后拒绝新执行，不淘汰旧收据。等待超时不会自动重发写操作，调用方应先查询原 attempt。Host 退役不可逆，新的 Host 必须使用新代际。

这些收据只在 Host 进程中有效。跨进程恢复依赖 Core 的持久化 attempt 和提交意图；生命周期层必须先确认旧写入者停止，再允许新代际领取。不得因 RPC 超时、Host 退出或收据丢失就直接重放传输。

统一错误由应用代码映射为固定消息，不转发上游原始错误；认证错误等待用户重新授权，限流附带有界延时。HTTP 429 即使返回 HTML 或非 JSON 正文也归一化为限流；有效 JSON 信封中的失败挂载 ID 保留用于清理。同账号其他作业遵循共享退避，每项最多三次尝试，耗尽后唤醒不重置预算。OpenList 的业务 code 500 不能整体映射为认证失败，具体归因由固定驱动适配器完成。

业务 schema v2 追加账号、绑定、远端映射、受管根、预览、订阅/扫描、作业/条目、attempt/领取、提交意图和 outbox。v1 本地目录与任务保持原意，升级前保存 v1 备份。当前账号写入口只接受凭据 UUID，拒绝 Cookie、密码和组件配置；同账号未确认的旧执行与同目标位置的重复领取由 SQLite 唯一约束阻止。完成项必须有长度和本地摘要，未完成项不能生成 outbox。

`planOnce` 从应用远端引用和经授权层映射的位置创建有界、冻结的文件批次；相同尺寸的可靠版本变化仍产生不同版本键，缺少可靠版本则显式标记弱比较。Core 先持久化快照再执行，重放读取原快照；卷授权、实体文件校验与不覆盖提交通过共享 `@media-marshal/media-core/files` 接入，纯计划函数不能代替这些检查。

Host 的 `StaticTransferRegistry` 只使用编译时显式注册的实例，先协商 source kind，再取得租约。没有匹配 Engine 时不取得租约、不写入文件；错误代际的租约立即释放。假实现仅由测试导入，不注册到生产入口。

状态机禁止传输或进度直接跳到完成：退出后等待校验，提交后凭完成记账证据才成为 `COMPLETED`。暂停需等待旧写入者停止，提交阶段的异常先进入恢复核对。当前业务测试覆盖预览、确认、账号预算、暂停/恢复、共享需求、有限重试、校验、提交与 outbox；独立测试 WebDAV Provider 也使用同一业务流程和真实 Rclone，生产注册表不包含该实现。

`SidecarBinaryResolver` 只接受绝对资源根、固定文件名与可信构建摘要，核对实际长度、Mach-O/PE 架构并拒绝符号链接和路径逃逸。外部组件摘要编译自固定锁文件，应用自有 Guardian 摘要由固定 Go 构建器生成；安装态的可信元数据从 ASAR 内读取，执行文件从安装资源根读取。签名后的摘要与最终打包清单由发行任务补齐，当前不把可变 userData 或系统 PATH 当作资源来源。

构建机先运行 `prepare.py`，再运行 `prepare_guardian.py`。完成桌面构建后，`node tools/desktop-sidecars/host_smoke.mjs` 验证真实 Host、系统 safeStorage、Guardian/OpenList、私有凭据注入与受限 RPC；该测试不连接网盘。`supervisor_smoke.mjs` 使用独立测试入口调用正式监管器，验证 Main/Core/Host/OpenList/Guardian 强杀和新代际恢复。两个入口均不进入发行包。

Main 对启动消息复核 OS 父子关系、可执行文件、完整命令与创建时间；不能用对端退出回执代替 OS 证据。接管前扫描本应用私有 session 标识下的旧进程，先停止 Guardian 再复核所有孩子；未知程序或查询失败阻止接管。Core 每 500 ms 接收父心跳，失联 5 秒后关闭数据库；生产数据库连接持有跨进程独占锁，旧连接未关闭时新 Core 不能开始写入。

Main 通过异步 safeStorage 维护账号级权威凭据，Host 只通过私有端口接收并存于内存。OpenList 每个 Host 代际使用单独目录与随机管理密码/JWT，只监听回环；管理授权先核对本次 JWT 签名和管理员身份，随后创建限定范围的只读 WebDAV 用户。启动最多三次；失去服务或 Guardian 时撤销旧执行，再由 Main 核验和回收。

设置页的默认诊断仅导出版本、核心/组件状态、账号数量与固定错误码，不读取原始文件。认证错误与组件失败保留不同错误码；用户暂停属于条目状态，不把正常运行的组件标为故障。Main 确认旧进程不存在后才清理旧 UUID 会话；暂存下载、完成目录与媒体库不在该清理范围。正式签名/公证尚无配置，发行验收保持未完成。

普通 Quark Provider 已注册到 Host，按绑定代际创建独立挂载和只读用户，候选验证失败不撤销旧绑定。上游不提供可核实 UID、稳定对象 ID、可靠 revision 或摘要，因此身份声明为不可用/路径身份，元数据只产生弱版本；Range 在逐文件验证前声明未知，M0 的单个 VIP 账号结果不外推到全部账号。

Provider 丢弃原始 `sign/raw_url/hash_info` 等未采用字段，只向 Core 返回规范化条目。私有分页游标用本次实例的签名绑定代际、父路径和页尺寸；总数变化、中断或未知响应不能返回完整结论。公开有界分页仍不等于锁定 OpenList 的上游网络有界，其驱动可能先拉取整目录；超时保持不完整，不推断源文件删除。

`SourceCredentialBroker` 以不透明句柄向 Engine 提供限定范围的 WebDAV 密钥，Cookie 不进入租约。OpenList 刷新的 Cookie 通过带确认的私有反向消息回 Main 的异步 safeStorage；Main 按绑定代际与引用核验，等待进行中的刷新后再轮换/解除，拒绝旧绑定更新活动引用。账号授权在 Host 内串行；关闭时撤销授权并拒绝迟到结果。

当前已追加 schema v3 的授权作业表，保留 v2 业务与匹配备份。Main 接收凭据后立即返回 Core 持久化作业；Cookie 不经过 Core，作业查询不含私有凭据引用。未知身份的重新授权保留账号与历史、暂停旧订阅，并要求重选范围；稳定身份不一致的候选不能提交。Main/Core 重启以活动绑定和保险箱引用恢复挂载，注入完成前 Core 阻断浏览，避免将恢复窗口误报为 Cookie 失效。

网页扫码登录由 `QuarkLoginController` 提供。`desktop.cloud.login` 只接受账号名称、可选账号 ID 和幂等请求 ID；Main 打开没有 preload 的夸克 HTTPS 窗口，独立随机内存 Session 禁止持久缓存、权限请求、下载和新窗口。检测目标地址的 `__pus` / `__puus` 后直接调用既有授权控制器，页面只收到授权作业。取消、五分钟超时、主窗口隐藏/重载、崩溃、升级和退出时清理网页会话；未提交前不创建账号。普通 Quark Provider 仍声明 Cookie 授权，不将网页扫码包装为官方 OAuth。固定 HTTPS 响应的 Electron 测试验证窗口、IPC、清理及提交边界，不能替代真实手机扫码验收。

Core 的 RemoteCatalog 为路径/稳定标识持有应用 UUID，并持久化实现映射；公开游标是有期的应用不透明标识，宿主游标和 locator 不进入 UI。每页至多 100 条，跨页去重和游标数量有上限；大小写与 Unicode 不擅自归一化为同一对象，缺页或路径失效不产生删除事实。Renderer 使用 StatefulService 管理账号、目录与条目预览，凭据草稿只保留在表单，提交/取消立即清空。

真实 Mac 有效账号的只读目录/stat 与 Core 重启证据见 `tools/desktop-sidecars/fixtures/quark-desktop-v4.2.7.json`。新增整文件验收见 `fixtures/quark-whole-file-v4.2.7-rclone-v1.75.2.json`：指定 604951500 字节视频通过真实窗口预览与确认，完成校验提交并保留重载/重启后的同一作业。上游仅有弱证据，本地 SHA-256 不宣称端到端验证或检测所有同尺寸替换。

RcloneCliEngine 已注册到正式宿主，复用受管 Guardian；单文件采用 copyto，多文件按同根精确原始清单复制，换行等特殊名称由单文件安全参数处理。执行快照与外部输入隔离，配置仅含 WebDAV 只读授权，使用 0700/0600 私有目录并在确认进程退出后清理；Rclone obscure 是兼容编码，不是系统加密。宿主先返回句柄再准备租约，进度约 1 Hz、原始日志有界且不出宿主，退出只代表可供 Core 核对。

账号静止窗口已从占位改为真实停止/租约回收，安装和解除凭据均不能绕过它。不能确认旧执行停止时保持 UNCERTAIN，不发布虚假 exited、不回收旧授权用于新写入；新 Engine 必须用内部 ExecutionUncertainError 表达此状态。正式宿主只接受 Main 私有注入的受管根，写入前验证卷、映射碰撞和空间，未知根直接拒绝。

schema v4 追加逐项执行计数、退避时间、独立观测、历史 attempt 成员和控制幂等收据，保留 v3 及对应备份。一次性范围异步预览，确认前不执行；预览有 15 分钟有效期，单次最多观察 10000 个对象且私有快照不超过 16 MiB，超限明确失败并保持未确认。Core 当前按单文件隔离 attempt；逻辑作业包含多个 attempt，账号最多一个写入者，应用最多同时四个账号。每项自动尝试最多三次，凭据失效和缺盘不自动循环。

Mac 卷策略使用 diskutil 的卷 UUID、目录 inode/创建时间及运行时设备号，探测真实大小写/Unicode 等价与路径长度。APFS/HFS 以实际卷上的独占创建、硬链接不覆盖和目录同步探测作为启用条件；本轮真实文件验收环境为 APFS，NAS/SMB 和其他文件系统拒绝自动写入，不能由此宣称 HFS 或移动磁盘全量兼容已验收。根与普通来源/目标双向禁止交叉覆盖，所有发现入口使用 `isManagedPrivatePath` 排除内部暂存区；未来整理接收端只接 completed 的幂等候选。

目录授权错误附带公开的 `directoryIssue`：固定原因和可选的配置 UUID，不包含原始组件输出、卷身份或标记内容。冲突引用只能来自 Core 已登记的来源、媒体目标或下载根；未知管理标记不得生成可信配置引用。Core 私有响应、Main 及公开 RPC 保留分类，Preload 的错误消息保留原因和处理指引。Main 在探测已知同目录前复用原授权 ID，Core 仍复核原卷及目录身份；复用 ID 不表示绕过管理标记或卷核验。

2026-10-25 的实际目录冲突来自两份应用配置：原配置有匹配管理标记、卷 UUID、目录 inode/创建时间的下载根记录，当前窗口的配置没有该授权。对实际 HFS+ 卷的自有临时文件探测通过了独占创建、硬链接不覆盖和目录同步，因此不能将本次失败归因于文件系统不支持。用户明确授权后，已先保存原配置的一致性备份及管理标记，再释放旧授权，由当前配置经原生对话框重新授权并验证重载可用；账号、历史及媒体文件未迁移。脱敏证据见 `tools/desktop-sidecars/fixtures/mac-directory-authorization-2026-10-25.json`，不据此宣称 HFS+ 完整下载链路通过。

共享 `ManagedRoot` 负责父目录、符号链接、同卷身份、逐项长度/可用上游摘要与本地 SHA-256、同卷硬链接不覆盖发布；只有 Core 决定文件完成。下载侧先复核远端证据，再保存提交意图，发布后事务写完成记录及唯一 outbox，最后清理自有暂存区。前案媒体 COPY 复用该文件组件，仍自行持有整理计划和提交记账，不直接操作下载表。这里不宣称对同 OS 用户恶意并发改目录提供 fd 相对路径隔离。

新 Host 代际通知仅在 Main 已完成 OS 回收后发出，Core 用它解除旧代际的不确定写入。超时、UNKNOWN 或页面重载都不充当停止证明；暂停中作业不计入新领取需求。逐点真实强杀与完整安装态矩阵仍继续验收，不能用模拟中断或单次整文件下载替代。Host 执行收据有容量上限；Main 在 128 个不同终止执行后暂停 Core 新领取，等待账号授权事务结束并通过既有退出/OS 回收流程重启 Core/Host，不淘汰当前代际收据。并发停止操作会撤销尚未完成的重启，避免退出期间重新启动写入者。


## 当前订阅、迁移与升级

schema v5 追加订阅运行状态、版本化扫描计划、控制收据及全局云端暂停归属；v6 为绑定追加原生对象 ID 命名空间。迁移均追加，核心备份保留匹配旧版本。父子订阅按网盘相对路径共享目标槽位；完整扫描才生成不可变需求，配置更新使旧扫描失效。扫描游标按会话隔离，浏览不会使后台扫描游标失效。当前 v29 先查询成功同步收据：同版本本地缺失仍跳过，原卷失联只记不可用，现存成果核对归属与摘要。强制重下使用独立目标变体并保留旧收据。

`cloud.account.writers-stopped` 仅由 Main 在实际宿主静止后调用，解除同代际丢失回执的占位；Host 的账号私有操作队列同时拒绝新 transfer.start。Main 唤醒恢复先核对原目录/卷并恢复凭据，再合并一次补扫；网络自动尝试有界，唤醒不会清空已经耗尽的重试预算。

绑定迁移只在同一可信账号、相同原生对象命名空间下逐项 stat 验证稳定 ID，验证后事务换代；只有路径、命名空间不同、超过有界范围或对象变化时要求重新选择。旧执行 token 不迁移，候选验证失败保留原绑定，回退也使用新代际。当前生产夸克驱动不具备上述稳定 ID 能力。

`IngestionOutbox` 独立于下载调度。生产接收端已接入 `IngestionPipeline`，按 item/version 持久化去重后确认，确认事务失败重投相同键。只下载、来源暂停、归属不明或目标未恢复时保持等待，不消耗投递预算。接收端沿下载需求的不可变来源版本选择整理策略，禁止按共享下载根猜测目标；候选识别、人工预览、COPY 和独立 Emby 交付分别记账。真实文件及固定服务器响应验证见[桌面整理流水线](./desktop-ingestion.md)，用户已有 Emby 的真实收录仍由变更 9.4 验收。

升级与恢复由 Main 先关闭账号事务、Core、Host 并再次核对 OS 进程，等待保险箱更新完成后执行。受限备份只包含业务 SQLite/WAL、凭据密文、组件私有状态及版本/摘要元数据，不复制下载根或媒体库。恢复先核对摘要、平台和兼容版本，使用持久化恢复日志；新 Core 启动前回滚未完成的文件组替换。未知旧格式记录为 schema 0（未声明），实际 SQLite 兼容性仍由 Core 拒绝检查。普通诊断不扫描或导出私有备份。当前 APFS 上真实 SIGKILL 与 Electron/安装态备份恢复分别记录，正式签名不因此完成。

schema v15 的恢复核对同时排队受管下载与已整理媒体／附属文件，队列由 Core 持久保存。缺盘等待、归属冲突需处理，不重放传输或 COPY；恢复核对期间不能使用旧 Emby 收录链接。启动前备份检查对手动／自动重启同样生效，详见[本轮 WAL 与恢复验收](./mac-upgrade-recovery-validation.md)。

## 成功收据与本地现状

schema v28 回填的 `sync_receipt` 与来源配置 ID、周期及普通任务历史分离；v29 将新下载完成项、提交状态、outbox 和成功收据放在同一事务中，附加不可修改的原文件证据。文件已发布但记账失败时仍按原 intent／inode 恢复，收据故障不能让完成项与 outbox 先成功。已完成记账后文件被移除则保持成功事实，不进入重传分支。

`SyncReceipts` 以源命名空间／对象／版本和目标授权／槽位查找。当前网盘使用应用稳定账号和远端引用，独立于来源名称及使用相同远端引用重新建立的等价来源。本地同步使用同一收据接口。生产夸克 Provider 当前声明 accountIdentity=unavailable、objectIdentity=path；CloudAccounts 重新授权会创建新根引用，因此跨重新登录的收据关联仍待完成。不能仅凭相同路径／尺寸认定两个登录属于原账号，也不能把这条分支列为 21.5 已通过；需先决定显式确认原账号与原范围，或增加可信账号身份校验。弱比较不将同尺寸的 mtime 变化提升为可靠新内容。

本地观测单独保存 PRESENT、REMOVED、CONFLICT 或 UNAVAILABLE。只有原根在读取前后均通过身份核验，且具体文件读取返回 ENOENT，才记录 REMOVED；缺盘、权限、符号链接或未知读取失败不能被转换为删除。现存文件必须匹配原卷、inode、创建时间、长度和 SHA-256，否则保留冲突。REMOVED 参与正常复用，预览与下载任务携带移除数量；不会创建新的传输。

收据不级联引用可清理的下载项。旧项仍存在时，新需求关联原项；旧任务明细已清理时，通过 `download_job_receipt` 关联历史成功事实，不伪造新传输或新 outbox。显式重新下载需完整预览和幂等确认，在独立目标变体创建新意图，保留旧结果。没有成功收据的未完成提交仍走原崩溃核对流程。

恢复整包备份时，已成功且本地移除的下载维持同步完成；现存文件继续按证据核对，原卷不可用等待恢复。这与媒体 COPY 目标缺失后转待处理的规则分开，不能用数据库恢复撤销或重建媒体文件。

## 真实资源与目录关系

统一来源选择一个远端目录，并用精确文件名限定一项资源，共 392,608,240 字节。保存草稿和完整预览时下载作业数为零；确认配置并执行一次后下载成功，周期仍关闭。随后按同一来源版本的可选整理策略交接一个候选，观察稳定后人工选择 TMDB 作品；真实分集列表核对 S01E01，COPY 预览确认目标尚不存在。

文件提交后保留来源，两个文件的 SHA-256 均为 `c063e18bfb819a879279e6667e32f3e3074e810549aa73cff552981a00fcf818`。上游仅提供弱版本证据，这个摘要证明本地下载成果与 COPY 一致，不宣称远端端到端摘要。Emby 最终同时匹配目标路径、作品标识和季集，交付状态成为 `COLLECTED`。打开条目的真实 Core／Main 路径已验证服务器一致及 URL 无密钥；该次外部浏览器调用由验收替身接收，不能算作系统浏览器交互验收。

首次识别失败时提示过于笼统，已补固定错误分类；当前构建可区分 TMDB 密钥／权限、限流、网络／代理、超时、响应无效及解析器问题，未知异常不回显原文。补丁后重启 Core，在同一任务上重试识别成功，再完成 COPY 和收录。记录中的最终构建摘要对应补丁后验收，下载、Core 与整应用重启的证据分别保留。

## 重复执行和交付故障

普通执行预览显示同一文件可复用；相同请求重复执行返回同一意图。把来源更新为每十五分钟扫描后，首轮及立即扫描都完整枚举一项、复用一项、冲突零项，扫描结果没有新下载作业 ID。普通再次执行产生了第二个逻辑下载作业，两个作业共享同一完成项。

整应用关闭后制作受限 SQLite 副本，只读查询证实：一个来源、两个逻辑下载作业、一个实际传输 attempt、一个完成项、一个整理候选、一个 COPY 操作和一个已收录交付。传输退出码为零，下载提交与 COPY 均已记账。Core 及整应用重启后计数不变，文件 inode 保持，来源版本、周期和暂停状态保留。验收来源最终暂停，避免继续执行周期扫描。

交付故障通过临时本机转发器制造：先转发真实服务器的身份、库及权限验证，再向客户端返回 503，实际观察两次失败请求。文件保持 DONE，待交付状态经 Core 重启保留。恢复原客户端地址和库绑定、关闭转发器后，点击「仅重试 Emby 交付」，最终由真实服务器响应核对为已收录；没有停止服务器或修改其运行设置，没有再次下载或 COPY。此项证明客户端的不可达恢复，不冒充物理服务器停机实测。

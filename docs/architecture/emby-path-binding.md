# Emby 目标路径关联与转换

设置中的媒体目标使用本机已授权目录。读取 Emby 全部媒体库的全部根目录后，应用按完整路径段、电影／剧集类型和包含关系发现关联。目标可以等于库根，也可以位于库根下。唯一兼容结果会自动选中；多个匹配要求明确选择，无匹配或类型冲突保留修复说明。暂不关联某个目标不妨碍独立 COPY。读取和发现关联不创建、更改媒体库或触发刷新；「验证并保存」会检查读取和刷新权限。

本机与容器、Windows 或远端服务器使用不同路径时，勾选「本机与服务端使用不同路径」，填写本机根、服务端根及路径风格，再重新发现关联。例如本机根 `/Volumes/媒体` 对应服务端根 `/data`，本机目标 `/Volumes/媒体/movies/新片` 对应 `/data/movies/新片`。界面显示两侧完整目标，文件始终写入本机授权路径。

转换保留相对路径，不按目录名猜测。不接受 `.`／`..` 越界、相似字符串前缀、盘符相对路径或不能在 Windows 表达的文件名；本机根须为真实目录，不沿符号链接扩大范围。Windows 服务端按 Windows 路径规则核对盘符、UNC 和大小写；POSIX 服务端按自己的路径区分大小写，不继承本机卷的名称等价策略。

schema v31 追加版本化绑定与验证请求收据，不改写历史迁移。绑定保存目标目录、服务器身份、连接版本、媒体库、具体库根及转换身份／版本。交付首次领取当前绑定后保存自身快照；不同绑定版本不能继续使用旧收录证据。重连或修改转换会清除旧条目证据，重新刷新和核对。重复验证请求复用已提交版本，不重复触发扫描。v30 直接路径关联保留；新进程仍须重新核对服务器及库根，不能仅凭磁盘快照恢复「已验证」。

交付查询使用转换后的服务端文件路径，仍核对作品 TMDB 标识、媒体类型、剧集季集和本机文件内容／身份。刷新成功仅表示扫描请求被接受。离线保留刷新意图并持久退避，修复后「仅重试 Emby 交付」不再 COPY。绑定或连接变化、库根／类型变化及目标文件变化均会拒绝旧条目；打开 Emby 前也重新查询服务器和库根。任务页逐项显示可信失败原因、原目标和关联设置入口，不展示原始服务端错误或密钥。

独立识别的关联使用逻辑 target ID，绑定中的 targetDirectory 仍记录实际目录 ID 和授权版本，二者不可混用。同目录的电影／剧集目标可分别关联；已受理计划保留逻辑身份。目标目录或类型替换生成新身份，历史任务继续可定位原关联。修正后沿用可证明匹配类型及实际目录的关联，目标不唯一时不按顺序猜测。

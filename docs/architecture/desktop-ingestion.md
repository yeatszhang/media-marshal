# 桌面整理流水线

实现位于 `packages/media-core/src/ingestion/`，只有 Core 写 SQLite。schema v7 追加来源授权、候选、计划、COPY 操作、媒体目标路由与独立 Emby 交付表，v8 追加附属文件的独立提交记录；迁移前沿用一致性备份机制，不读取 Java 数据库。Main 通过 safeStorage 保存服务密钥，Core 启动后经私有通道注入内存，公开设置只有是否已配置的布尔值。

来源可为普通目录或受管下载，界面明确区分。受管接收器依据已完成下载及 RECORDED 提交意图接收 `itemId/versionKey`；outbox 重投和 completed 补扫走相同持久唯一键。确认回执丢失后不增加候选，不重传原文件；completed 内没有提交记录的外部文件不被接收，staging 和 `.media-marshal` 不属于候选入口。接收成功只代表候选已保存，不产生媒体 DONE。

启动、每十秒、文件事件提示和手动扫描共用就绪检查；事件经有界延迟合并，同一来源扫描合并为一次执行，事件丢失由定时补扫补偿。观察使用单调时钟，至少连续稳定 120 秒，超长调度停顿、重启、唤醒或暂停恢复会重新计时；零字节和临时文件不能就绪。来源目录句柄、卷身份、实际路径及文件身份同时核验，不能因路径名称相同而绑定替代硬盘。官方客户端的完整行为矩阵尚未验证，当前全部来源保持人工确认，稳定尺寸不能作为完整下载证明。正常下载的局部实测见[官方客户端磁盘观察](./mac-quark-client-observation.md)。 本地忽略的默认／显式空列表／自定义语义及样片判定见[统一来源说明](./source-rules.md#本地发现与忽略)。监听失效仍定时补扫；已知文件不可读或缺失时更新为不可用而保留记录。 整个来源目录失联也清空主文件和附属文件观察，恢复同一原目录后重新稳定至少 120 秒；同名替代目录不能接管。

统一来源页通过原生目录选择授权各来源的媒体目标，可选择电影、剧集或按识别类型整理。候选按来源版本的目标及策略快照预览，不被另一来源或设置页的默认路由覆盖；设置页仍可维护已有 Emby 库映射。来源与所有目标、受管根及历史操作保留的目标不能相互包含。Mac 写目标沿用 APFS/HFS+ 原卷探测及实际硬链接提交能力测试；其他文件系统不能证明相同保证时阻止写入，不将未验证平台算作兼容结果。

每个 COPY 操作持久记录 PLANNED、COPYING、VERIFIED、FILE_COMMITTED 与 RECORDED。内容流式写入目标卷的私有暂存区，复制后重新读取来源摘要并核验文件快照，再核对暂存长度和摘要。正式发布使用不覆盖的硬链接；目标抢占或归属证据不符转需处理。已验证的操作恢复只补提交与记账，来源始终保留；清理只处理具有本操作标记的暂存文件。

macOS 的 APFS／HFS+ 实测支持上述提交，独立进程抢建同名目标也不能覆盖或认领；exFAT 原生硬链接返回不支持，因此阻断作为下载／整理目标，仍允许只读来源。卷身份、权限和能力继续逐次检查。测试使用自有磁盘映像，详细边界与重复命令见[文件系统与提交验收](./mac-filesystem-commit-validation.md)。

容量在预览、确认和实际复制前复核，计入其他已领取操作及十六 MiB 余量。真实临时文件测试以受控可用容量报告验证空间不足阻断及原操作恢复；Mac 上实际撤销文件读取权限、复制过程中改写来源、同尺寸篡改暂存内容，都不能发布正式文件。三 MiB 以上文件另验证每块最多一 MiB、同目标设备暂存及来源保留，不以物理填满用户磁盘制造故障。

附属文件沿 Java `MediaProcessPipeline.moveAssociatedFiles` 的同基名规则：保留语言／强制字幕后缀，按主视频新基名重命名字幕、用户 NFO、图片及 MD5；通用 `poster.jpg`、`folder.jpg`、`cover.jpg` 保留原名。无关文件不接入；可在预览取消附属文件，未稳定字幕不会迫使主视频一起复制。每项有独立提交与失败记录，主视频 DONE 不代表整批成功；字幕失败时作业 PARTIAL_FAILED，重试只处理失败附属项，视频和来源保持。相关真实文件测试覆盖多格式逐项成功、主动排除与主成功／字幕失败的独立重试。

识别在文件观察之后，通过 SQLite 事务重新读取候选并领取任务；并发请求返回同一任务，不留下无候选关联的任务。确认使用持久操作及候选唯一约束，重复确认返回原操作。暂停在未发布阶段中断流式复制，保留来源和计划；恢复后从首次重新观察起再计算稳定窗口。正式发布后的恢复只补记账，不回滚文件。音乐、ISO 和蓝光结构中的视频显示已跳过，不能进入普通视频识别。

来源级变化使用候选自己的取消信号，不取消整轮调度。暂停 A 时 B 的复制继续；共享根中暂停策略 A 不会中断仍有有效需求的策略 B，主视频已经 DONE 的字幕也按候选协调。观察键包含策略及具体路径，同一目标下不同文件的窗口相互独立。重复接收已下载的字幕会继续观察，Core 重开后也能重新建立完整窗口。全局暂停和关闭仍统一中断活动工作，并等待资源释放；正式提交后的记账与 Emby 交付保持独立。

`ingestion-crash.test.ts` 在独立进程加载当前源码编译结果，持有真实 SQLite 独占锁并运行整理类，通过实际 `SIGKILL` 验证计划、部分写入、已校验、已发布未记账、提交状态已写、记账完成和交付记录补建。未校验操作恢复后重新观察来源，已校验操作不再读取来源内容；已发布文件保持 inode。外部抢占目标时保留第三方文件并转需处理，其他操作的暂存文件不会被清理。这是文件／记账边界验收，Main／Utility Process 的整机故障另由对应窗口和安装态测试覆盖。

预览可选择同名字幕、附属文件及通用封面，并逐项列出目标；这些文件同样需要稳定观察。schema v8 为每个附属文件独立保存尝试、摘要与提交阶段，主视频已完成而字幕失败时作业显示部分失败，重试只处理失败附属文件，不复制主视频。初步真实文件用例已覆盖字幕目标抢占与独立重试；批量确认见识别文档，修正及完整附属文件/崩溃矩阵仍按前案独立任务继续实施，不能据此勾选整条任务。

文件 DONE 与 Emby 交付独立。连接验证读取服务器身份、库路径和读取权限，并实际验证刷新权限；电影与剧集目录分别绑定服务端库。服务端路径必须在这台 Mac 上可访问并包含目标，不自动猜容器或远程 NAS 映射。接受刷新不代表收录成功，Emby 请求不继承 TMDB 代理。

连接保存后，新的 Core 仍须重新验证身份、库路径、类型和读取／刷新权限，不能把旧进程的有效标记直接当作当前证据。有效复核保留原绑定版本。暂时离线保留绑定，至少三十秒后再试；认证失败或服务器／库配置变化使旧证据失效，等待用户修复。单个目标缺盘仍按目标独立等待，不把路径不可达解释为需要重装服务器。

电影目标接受电影库或混合库，剧集目标接受剧集库或混合库；同一目标按 AUTO 接收两类媒体时需要混合库。`CollectionType` 未指定表示混合内容，依据 [Emby 官方说明](https://dev.emby.media/doc/restapi/Browsing-the-Library.html)。其他库类型被拒绝；运行期间也复查类型，不能只在第一次连接时核对。根目录与合法子目录均可使用，目录不必为空，绑定不创建整理任务或移动原有媒体。

交付意图与文件记账在同一事务中写入，启动也补建缺失意图。按连接版本在三十秒窗口合并刷新，故障退避从三十秒增长到十五分钟并持久保存；认证失败暂停整个连接，修复后重新验证。每十五秒分页核对限定库，最多等待十分钟。核对同时匹配目标路径、电影/剧集类型、作品 TMDB 标识和季集；集级 TMDB ID 不冒充剧集作品 ID，须读取其 Series 的 ProviderIds。证据缺失、冲突或超时保留待处理，重试交付不调用 COPY。打开 Emby 前再次检查服务器身份，地址不携带密钥。

有待交付记录时，Core 重启复核也遵守已保存的刷新窗口和故障退避。复核实际发送的刷新由同版本已到期交付共享，之后直接等待收录，不在同一轮再次发送；尚未到期的任务保留自己的等待时间。复核失败同样持久累加退避，反复重启不会将其归零。

同库一轮任务共享分页结果，分页总数变化、重复成员或缺页不能作为部分成功；Series 批量响应也拒绝重复或非请求成员。多版本用 `MediaSources.Path` 定位，仍需唯一作品与目标文件证据。条目身份核对期间连接版本、凭据或交付状态变化会拒绝迟到结果；Main 再限定 HTTP(S) 服务器、精确子路径和条目参数，禁止重定向传递密钥及额外凭据参数。

接口依据：[服务器身份](https://dev.emby.media/reference/RestAPI/SystemService/getSystemInfo.html)、[媒体库分页](https://dev.emby.media/reference/RestAPI/LibraryStructureService/getLibraryVirtualfoldersQuery.html)、[限定库条目分页](https://dev.emby.media/reference/RestAPI/ItemsService/getItems.html)、[刷新权限](https://dev.emby.media/reference/RestAPI/LibraryService/postLibraryRefresh.html)。

验证命令为 `npm test -- packages/media-core/src/domain packages/media-core/src/ingestion`，以及 `npm test -- apps/desktop/src/main/cloud/downloads.test.ts -t '生产接收端'`。这些是实际 SQLite、真实本地文件和固定 HTTP 响应测试；单资源真实账号下载、用户已有服务器收录及交付故障恢复另见[本轮验收记录](./mac-unified-source-validation.md)。完整 Mac 安装态回归及当前工作树的新安装包仍继续进行。既有 0.2.1 DMG 不含本轮流水线，不能沿用它的通过记录证明新代码已安装验收。

本地 COPY 不依赖 Emby 连接验证，现有电影和剧集库直接复用；Emby 刷新／收录为独立步骤。单资源真实链路通过后，嵌套签名公证、Mac Intel 运行和其余未完成任务仍继续验收；本轮未生成新 DMG，不归档变更或标记正式发行。

## 本地资产版本与全量内容复核

schema v16 将本地候选的属性键 `attribute_key` 与资产版本 `version_key` 分开。每条来源及相对路径由数据库部分唯一索引限定一个当前候选，历史候选、任务、COPY 计划和已提交媒体保留。普通扫描仍逐文件检查属性，不依赖目录修改时间；变化时产生新一代资产并重新观察，未执行的旧任务失去领取权。即使文件从 A 改为 B 后又改回 A，也不复用旧的已处理版本。同一版本的扫描、监听、识别领取和确认仍通过原有合并、事务及唯一约束去重。

「待处理」中的「全量内容复核」用于已经确认的本地目录来源。它按照当前忽略和普通视频规则枚举，并合并已知当前路径，因此缺失的已知文件也会留下逐项结果。每次最多一万项，超出后明确要求缩小来源；本次枚举后新增的文件留待下一次补扫或复核。网盘来源继续沿已记账下载项和来源策略接入，远端弱版本替换使用来源页的「强制重新下载」，不把本地摘要当成远端内容证明。

复核只读取来源，每块最多一 MiB，并连续读取两轮 SHA-256；读取前后核对文件快照、原目录和原卷。已有可信摘要不同时，创建新的观察候选，并阻断旧预览；属性没有变化也能发现替换。没有历史摘要时只建立当前内容基线，不能断言此前未被替换。COPY 的已验证源摘要同时作为基线保存；升级时仅从已记账 COPY 的持久证据补齐历史基线，不重新读取或写入个人媒体。

复核是持久作业，开始动作立即返回作业 ID；同来源并发点击合并为一项，请求标识可查询原收据。界面显示进度、当前路径、变化／基线／失败数量和分页逐项结果。部分文件失败不会冒充整项成功，原目录失联或暂停时保留未完成项等待恢复，配置版本变化则结束旧作业并要求重开。取消不撤销已提交的复核结果，也不把尚未读取的文件标为通过。作业运行期间不允许同来源的新识别、确认或重试 COPY；已有活动主文件或附属 COPY 时拒绝启动复核，其他来源可继续处理。

整理确认的事务会再次比对当前候选及其摘要；即使目录核验等待期间复核已经结束，也不能提交不含新证据的旧预览。旧 COPY 计划从未校验阶段恢复时，同样使用已保存的来源摘要核对内容，不能因旧计划尚无摘要就接受静默替换。

摘要计算在事务外，资产版本变化与该文件的复核结果在同一事务提交。关闭会中断正在读取的文件并等待执行结束；未完成项跨数据库重开或进程强杀保留，恢复后只读尚未记账的项，不重新复制媒体。复核从不代替 120 秒稳定观察、作品识别、人工确认或 Emby 收录。

2026-10-25 的定向测试覆盖真实文件的同属性替换、A→B→A、并发领取、取消、目录失联、配置变更、事务失败与数据库重开。为构造同属性替换，测试真实改写文件内容，并注入粗粒度时间属性报告；这不表示 APFS 的真实 ctime 可保持不变。独立子进程在第一项记账、第二项读取时收到实际 SIGKILL，恢复后保留同一作业且只读取第二项。真实 Electron 开发构建另验证实际 IPC、逐项错误、窗口重载和 Core 重启，目录对话框使用受控替身；未在个人媒体目录运行全量读取。

复现命令：`npm test -- packages/media-core/src/ingestion/pipeline.test.ts packages/media-core/src/infrastructure/database.test.ts packages/contracts/src/contracts.test.ts apps/desktop/src/renderer/src/content-reviews.test.tsx apps/desktop/src/main/cloud/ingestion-crash.test.ts`；窗口检查使用 `npm run desktop:build` 后执行 `npm run test:desktop -- --grep '全量内容复核经实际 IPC'`。

内容复核实现（`aa1a5b0`）的回归为 488 项核心／契约／组件测试通过、13 项跳过，24 项真实 Electron 开发构建检查通过。类型、依赖边界、桌面构建、OpenSpec 严格校验与文档构建通过；LikeC4 1.60.0 校验并重新导出四个视图。该结果不替代 Mac Intel、正式签名或安装态验收。

来源删除与恢复保留同一候选、任务和 COPY 计划；实际写入须先暂停并等待停止，恢复后重新观察，沿原计划处理。已完成文件及独立 Emby 交付不回滚。界面和生命周期并发检查见[统一来源的可恢复删除](./source-rules.md#可恢复删除)。

待确认任务支持单条／批量编辑识别字段，保存与重新匹配均不创建 COPY；整理预览同时绑定识别版本。具体字段、错误和恢复契约见[人工识别字段](./desktop-recognition.md#人工识别字段与重新匹配)。

待确认任务可从目录共同候选或文件勾选生成持久批量预览，跨项检查真实季集、主文件及附属文件目标。只有全部计划可用并明确确认完整范围后才逐项提交原 COPY；停止、部分失败和收据补记均保留已提交文件。详见[共同作品与逐文件批量整理](./desktop-recognition.md#共同作品与逐文件批量整理)。

## 修正所需的独占改名原语

修正须先持久保存旧／新目标和文件证据，再执行不覆盖的目标变更。Mac 已有独立 Node-API 8 开发原语，调用 `renameatx_np` 的 `RENAME_EXCL` 并区分未改名、已改名及需核对结果；不使用普通 `rename` 的预检代替排他提交。Apple 将此能力按文件系统声明，见 [Apple 独占改名说明](https://developer.apple.com/documentation/foundation/urlresourcevalues/volumesupportsexclusiverenaming)。本机自有映像证明 APFS、HFS+ 成功改名且阻止目标覆盖，exFAT 不支持，跨卷调用保持来源并返回明确分类；全部测试映像已卸载清理。

原语复制并独占持有目录 FD，放到工作线程执行，限制 64 项等待；不提供任意路径、命令、删除或自动回滚。Core 仍须校验授权、原卷、实际文件与摘要，调用前持久化计划，改名后核对并补记。进程中断或返回需核对状态不能直接重放或删除文件。

根内版本逐层进入目录 FD，拒绝父级符号链接及跨设备子挂载；来源身份失效或根跨卷时不创建目标目录。跨卷复制另用 `linkBeneath` 发布目标卷暂存文件，保留原暂存锚点供日志恢复；它不是改名不受支持时的降级路径。资源加载核对 manifest／二进制摘要与 Mach-O 架构。`ManagedRoot` 已提供私有隔离、完整摘要、发布恢复与仅按原证据回收私有文件的接口；同内容的外部文件不能代替原 inode。2026-10-26 的 16 项 Electron Node 文件测试及 APFS／HFS+／exFAT 自有映像结果见原语目录，exFAT 两项均返回不支持，未执行回退操作。

上述原语已用于下方内部文件日志组件，尚未接入用户修正入口或安装包。任务 5.6／5.7 继续保持未完成；业务附属文件、历史链、整条修正强杀恢复、x64 运行和签名安装均须后续验收。构建入口为 `npm run desktop:prepare-native-files`，原生测试为 `npm test -- packages/media-core/src/files/rename-exclusive.test.ts`；完整开发契约和脱敏结果位于 `tools/desktop-files/README.md` 与该目录 `fixtures/`。

## 修正文件的持久步骤

schema v21 增加 `media_file_relocation`，文件执行器位于 `files/relocations.ts`。每个步骤引用原修正成员，冻结旧／新媒体目标授权、相对路径和原文件的 inode／出生时间／修改时间／大小／完整 SHA-256；数据库禁止修改原计划。只有已登记的媒体目标可参与；原文件的业务归属仍须由修正预览从已整理收据核验，不能用文件存在或自报摘要取得归属。不按下载目录路径认领文件，也不要求原下载来源在线。重复步骤 ID 只能返回同一计划；旧／新位置及目录前缀与另一活动步骤相交时拒绝规划。文件 DONE 后仍保留位置占用，所属修正成员的历史事务标为 RECORDED 后才释放。

同路径只核对并生成文件收据。其余同卷变更先把旧文件独占改名到本步骤 UUID 的私有隔离位置，再独占改名到新位置；大小写变化也沿这条路径。每次 IO 前已有对应阶段，IO 后核对强证据并同步目录。若改名已发生但回执未写，重启根据隔离位置或新位置补记；陌生文件、多个同时存在的位置或不符证据保持 NEEDS_ATTENTION，不自动逆向或删除。

跨卷计划先持久保存 COPY 尝试，流式写入新卷私有暂存，核对源快照、原摘要和暂存摘要后才发布。新目标发布后保留暂存锚点，再把旧媒体隔离到旧卷私有位置；删除隔离文件前另记 REMOVING_OLD 意图。新文件正确但旧卷离线时停在原阶段等待，不能报整个文件完成或回滚新目标；删除已发生但回执未写时，只有原公开位置与私有隔离位置都缺失、新目标证据正确，才可补记。历史事务完成前若新目标缺失，只允许用原暂存锚点重新发布；陌生目标保持冲突，不从下载来源重新复制。历史事务完成后另行清理暂存锚点。原下载文件不参与这些操作。

全局暂停和退出可中断流式复制，在途原生改名则等待确定结果、核对并记录安全阶段；恢复继续原步骤。COPY 中断的暂存只按本 attempt 标记清理，随后使用新 UUID，不向半文件追加。临时磁盘／空间／权限问题持久等待，证据冲突逐项保留原因；显式重试不替换计划。

2026-10-26 的真实 SQLite／隔离文件测试覆盖同路径、大小写、占用、回执丢失、跨卷计划分支、暂停、暂存清理和活动位置保留；六个独立 Core 进程在复制、旧目标隔离、新位置发布、旧隔离删除及文件完成等检查点收到 SIGKILL 后，以同一步骤恢复。单元用例以不同授权卷身份驱动 COPY 分支，不作为真实跨设备证据。独立工具 `tools/desktop-files/check-relocations.mjs` 使用自有 HFS+ 映像验证真实双向跨卷 COPY 与 HFS+ 本卷改名，结果单独记录于该目录 fixtures。

当前执行器仍是内部组件，尚未接入普通视频修正预览、历史／Emby 事务、逐项 UI 或安装包；原始任务的 DONE／CORRECTED 状态不由文件执行器自行更改。这些边界及附属文件、批量范围调度仍须由 5.6／5.7 完成，不能据上述组件恢复测试勾选整项任务。

# 桌面整理流水线

实现位于 `packages/media-core/src/ingestion/`，只有 Core 写 SQLite。schema v7 追加来源授权、候选、计划、COPY 操作、媒体目标路由与独立 Emby 交付表，v8 追加附属文件的独立提交记录；迁移前沿用一致性备份机制，不读取 Java 数据库。Main 通过 safeStorage 保存服务密钥，Core 启动后经私有通道注入内存，公开设置只有是否已配置的布尔值。

来源可为普通目录或受管下载，界面明确区分。受管接收器依据已完成下载及 RECORDED 提交意图接收 `itemId/versionKey`；outbox 重投和 completed 补扫走相同持久唯一键。确认回执丢失后不增加候选，不重传原文件；completed 内没有提交记录的外部文件不被接收，staging 和 `.media-marshal` 不属于候选入口。接收成功只代表候选已保存，不产生媒体 DONE。

启动、每十秒、文件事件提示和手动扫描共用就绪检查；事件经有界延迟合并，同一来源扫描合并为一次执行，事件丢失由定时补扫补偿。观察使用单调时钟，至少连续稳定 120 秒，超长调度停顿、重启、唤醒或暂停恢复会重新计时；零字节和临时文件不能就绪。来源目录句柄、卷身份、实际路径及文件身份同时核验，不能因路径名称相同而绑定替代硬盘。官方客户端的完整行为矩阵尚未验证，当前全部来源保持人工确认，稳定尺寸不能作为完整下载证明。正常下载的局部实测见[官方客户端磁盘观察](./mac-quark-client-observation.md)。 本地忽略的默认／显式空列表／自定义语义及样片判定见[统一来源说明](./source-rules.md#本地发现与忽略)。监听失效仍定时补扫；已知文件不可读或缺失时更新为不可用而保留记录。 整个来源目录失联也清空主文件和附属文件观察，恢复同一原目录后重新稳定至少 120 秒；同名替代目录不能接管。

统一来源页通过原生目录选择授权各来源的媒体目标，可选择电影、剧集或按识别类型整理。候选按来源版本的目标及策略快照预览，不被另一来源或设置页的默认路由覆盖；设置页仍可维护已有 Emby 库映射。来源与所有目标、受管根及历史操作保留的目标不能相互包含。Mac 写目标沿用 APFS/HFS+ 原卷探测及实际硬链接提交能力测试；其他文件系统不能证明相同保证时阻止写入，不将未验证平台算作兼容结果。

每个 COPY 操作持久记录 PLANNED、COPYING、VERIFIED、FILE_COMMITTED 与 RECORDED。内容流式写入目标卷的私有暂存区，复制后重新读取来源摘要并核验文件快照，再核对暂存长度和摘要。正式发布使用不覆盖的硬链接；目标抢占或归属证据不符转需处理。已验证的操作恢复只补提交与记账，来源始终保留；清理只处理具有本操作标记的暂存文件。

macOS 的 APFS／HFS+ 实测支持上述提交，独立进程抢建同名目标也不能覆盖或认领；exFAT 原生硬链接返回不支持，因此阻断作为下载／整理目标，仍允许只读来源。卷身份、权限和能力继续逐次检查。测试使用自有磁盘映像，详细边界与重复命令见[文件系统与提交验收](./mac-filesystem-commit-validation.md)。

容量在预览、确认和实际复制前复核，计入其他已领取操作及十六 MiB 余量。真实临时文件测试以受控可用容量报告验证空间不足阻断及原操作恢复；Mac 上实际撤销文件读取权限、复制过程中改写来源、同尺寸篡改暂存内容，都不能发布正式文件。三 MiB 以上文件另验证每块最多一 MiB、同目标设备暂存及来源保留，不以物理填满用户磁盘制造故障。

附属文件沿 Java `MediaProcessPipeline.moveAssociatedFiles` 的同基名规则：保留语言／强制字幕后缀，按主视频新基名重命名字幕、用户 NFO、图片及 MD5；通用 `poster.jpg`、`folder.jpg`、`cover.jpg` 保留原名。无关文件不接入；可在预览取消附属文件，未稳定字幕不会迫使主视频一起复制。每项有独立提交与失败记录，主视频 DONE 不代表整批成功；字幕失败时作业 PARTIAL_FAILED，重试只处理失败附属项，视频和来源保持。相关真实文件测试覆盖多格式逐项成功、主动排除与主成功／字幕失败的独立重试。

识别在文件观察之后，通过 SQLite 事务重新读取候选并领取任务；并发请求返回同一任务，不留下无候选关联的任务。确认使用持久操作及候选唯一约束，重复确认返回原操作。暂停在未发布阶段中断流式复制，保留来源和计划；恢复后从首次重新观察起再计算稳定窗口。正式发布后的恢复只补记账，不回滚文件。音乐、ISO 和蓝光结构中的视频显示已跳过，不能进入普通视频识别。

`ingestion-crash.test.ts` 在独立进程加载当前源码编译结果，持有真实 SQLite 独占锁并运行整理类，通过实际 `SIGKILL` 验证计划、部分写入、已校验、已发布未记账、提交状态已写、记账完成和交付记录补建。未校验操作恢复后重新观察来源，已校验操作不再读取来源内容；已发布文件保持 inode。外部抢占目标时保留第三方文件并转需处理，其他操作的暂存文件不会被清理。这是文件／记账边界验收，Main／Utility Process 的整机故障另由对应窗口和安装态测试覆盖。

预览可选择同名字幕、附属文件及通用封面，并逐项列出目标；这些文件同样需要稳定观察。schema v8 为每个附属文件独立保存尝试、摘要与提交阶段，主视频已完成而字幕失败时作业显示部分失败，重试只处理失败附属文件，不复制主视频。初步真实文件用例已覆盖字幕目标抢占与独立重试；批量确认、修正及完整附属文件/崩溃矩阵仍按前案独立任务继续实施，不能据此勾选整条任务。

文件 DONE 与 Emby 交付独立。连接验证读取服务器身份、库路径和读取权限，并实际验证刷新权限；电影与剧集目录分别绑定服务端库。服务端路径必须在这台 Mac 上可访问并包含目标，不自动猜容器或远程 NAS 映射。接受刷新不代表收录成功，Emby 请求不继承 TMDB 代理。

连接保存后，新的 Core 仍须重新验证身份、库路径、类型和读取／刷新权限，不能把旧进程的有效标记直接当作当前证据。有效复核保留原绑定版本。暂时离线保留绑定，至少三十秒后再试；认证失败或服务器／库配置变化使旧证据失效，等待用户修复。单个目标缺盘仍按目标独立等待，不把路径不可达解释为需要重装服务器。

电影目标接受电影库或混合库，剧集目标接受剧集库或混合库；同一目标按 AUTO 接收两类媒体时需要混合库。`CollectionType` 未指定表示混合内容，依据 [Emby 官方说明](https://dev.emby.media/doc/restapi/Browsing-the-Library.html)。其他库类型被拒绝；运行期间也复查类型，不能只在第一次连接时核对。根目录与合法子目录均可使用，目录不必为空，绑定不创建整理任务或移动原有媒体。

交付意图与文件记账在同一事务中写入，启动也补建缺失意图。按连接版本在三十秒窗口合并刷新，故障退避从三十秒增长到十五分钟并持久保存；认证失败暂停整个连接，修复后重新验证。每十五秒分页核对限定库，最多等待十分钟。核对同时匹配目标路径、电影/剧集类型、作品 TMDB 标识和季集；集级 TMDB ID 不冒充剧集作品 ID，须读取其 Series 的 ProviderIds。证据缺失、冲突或超时保留待处理，重试交付不调用 COPY。打开 Emby 前再次检查服务器身份，地址不携带密钥。

有待交付记录时，Core 重启复核也遵守已保存的刷新窗口和故障退避。复核实际发送的刷新由同版本已到期交付共享，之后直接等待收录，不在同一轮再次发送；尚未到期的任务保留自己的等待时间。复核失败同样持久累加退避，反复重启不会将其归零。

同库一轮任务共享分页结果，分页总数变化、重复成员或缺页不能作为部分成功；Series 批量响应也拒绝重复或非请求成员。多版本用 `MediaSources.Path` 定位，仍需唯一作品与目标文件证据。条目身份核对期间连接版本、凭据或交付状态变化会拒绝迟到结果；Main 再限定 HTTP(S) 服务器、精确子路径和条目参数，禁止重定向传递密钥及额外凭据参数。

接口依据：[服务器身份](https://dev.emby.media/reference/RestAPI/SystemService/getSystemInfo.html)、[媒体库分页](https://dev.emby.media/reference/RestAPI/LibraryStructureService/getLibraryVirtualfoldersQuery.html)、[限定库条目分页](https://dev.emby.media/reference/RestAPI/ItemsService/getItems.html)、[刷新权限](https://dev.emby.media/reference/RestAPI/LibraryService/postLibraryRefresh.html)。

验证命令为 `npm test -- packages/media-core/src/domain packages/media-core/src/ingestion`，以及 `npm test -- apps/desktop/src/main/cloud/downloads.test.ts -t '生产接收端'`。这些是实际 SQLite、真实本地文件和固定 HTTP 响应测试；单资源真实账号下载、用户已有服务器收录及交付故障恢复另见[本轮验收记录](./mac-unified-source-validation.md)。完整 Mac 安装态回归及当前工作树的新安装包仍继续进行。既有 0.2.1 DMG 不含本轮流水线，不能沿用它的通过记录证明新代码已安装验收。

本地 COPY 不依赖 Emby 连接验证，现有电影和剧集库直接复用；Emby 刷新／收录为独立步骤。单资源真实链路通过后，嵌套签名公证、Mac Intel 运行和其余未完成任务仍继续验收；本轮未生成新 DMG，不归档变更或标记正式发行。

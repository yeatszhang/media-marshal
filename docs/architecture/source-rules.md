# 统一来源配置与版本

`SourceRules` 在 Core 中协调配置，使用现有业务 SQLite；Main 负责原生目录权限。账号连接不创建来源，来源草稿不创建本地规则、订阅或下载任务。账号凭据、Provider 映射、传输状态均不进入来源配置。

## 身份与关联

| 记录 | 职责 |
| --- | --- |
| `source_rule` | 稳定来源 ID、local/cloud 类型、有效版本、草稿修订、暂停状态和当前执行关联 |
| `source_rule_version` | 不可修改的有效配置及本地规则、订阅、整理来源和目标授权引用 |
| `source_rule_preview` | 绑定有效版本和草稿修订的确认凭据；网盘预览引用完整下载范围 |
| `source_rule_command` | 配置／确认幂等收据；同请求标识的不同内容被拒绝 |
| `download_source_demand` | 下载作业所属的来源 ID 和配置版本；不随后续编辑改写 |

本地来源必须有输入目录和 COPY 整理目标，网盘来源必须有账号、远端引用和下载根，可以不启用整理。外部客户端标签只属于本地来源。配置使用严格的判别联合，拒绝 Cookie、凭据引用、组件参数和由 Renderer 提交的授权对象。

有效配置只能经来源命令修改。已关联的旧本地保存、旧订阅配置和旧受管整理修改入口不能再独立改变配置；旧查询及历史仍可保留。订阅表保存执行配置及扫描事实；来源命令在同一短事务中更新它与来源引用，不增加第二个可独立编辑的配置入口。不可修改的版本快照用于历史和执行核对。

## 动作与失败边界

1. `source-rules.configure` 保存草稿，带上预期有效版本、草稿修订与幂等请求 ID。只增加草稿修订，原有效版本继续使用。
2. `source-rules.preview` 固定该修订的配置；网盘枚举未完成、存在冲突或过期时不能确认。`get-preview` 只查询，不重放扫描。
3. `source-rules.apply` 由 Main 核对原生授权后进入私有 Core 动作。Core 重新核对配置版本、目录和运行安全点；原生授权及异步准备结束后再次核对，不能用旧预览提交并发新草稿。
4. 在一个 SQLite 事务内提交本地规则／订阅、有效配置快照、关联和幂等收据。事务失败保留原有效配置；提交成功后才安装监听、取消旧扫描及协调过期下载需求。媒体文件不由配置事务修改。

确认只下载配置不会要求 TMDB、媒体目标或 Emby，也不会自动启用周期扫描。仅确认配置不下载；选择「确认并执行一次」时，`runOnce` 将配置与一次性意图写入同一事务，页面重载不会留下配置已确认而执行意图丢失的空档。周期扫描显式启用后，现有订阅引擎按已确认范围调度；每个作业在创建事务中保存来源版本。来源变更不会改写已持久化的 attempt 计划或旧版本快照。

本地规则存在活动 COPY 或附属文件操作时，拒绝本次配置确认，提示到达安全点后重试，当前操作保留原计划。已提交文件及其交付记录保持独立。订阅的 `configuration_version` 同时用于运行栅栏，重新授权也可能推进它；该值不得倒退，不要求与来源的用户配置版本始终相同。

原生目录授权与来源启用分开记账。目标经过真实路径与卷核验后先登记为未启用授权，再初始化磁盘管理标记；配置事务失败时不创建执行来源，但保留可核对的授权身份，Main 重试时复用该 ID，避免留下无法匹配当前配置的标记。读取该授权的私有动作不暴露给 Renderer。

`source-rules.get/list` 返回草稿与有效配置、版本及应用 UUID，不返回授权对象和凭据。Preload 只暴露这些具体方法。公开 Core 通道不能绕过 Main 直接确认目录授权。

## 本地目录健康

来源卡片将编辑、暂停／恢复和删除操作放在标题及版本之后，路径和目录健康信息放在操作下方，避免长路径及健康详情将暂停按钮挤出最小窗口。920×640 窗口的首屏可见断言保留，相关四项打包窗口回归和二十五项组件测试通过；[实际窗口截图](/desktop/source-card-actions-minimum.png)使用隔离目录与受控目录选择结果，不作为系统选择器或托盘实测。

`source-rules.local-health` 只接受当前已确认的本地来源 ID、有效版本和生命周期版本，每批最多 25 项且不能重复。Core 使用已安装的来源／目标根句柄检查原目录身份、实际路径、卷文件系统与访问权限；输入需可读，目标需可写。检查不发现文件、不识别、不创建下载或 COPY，也不切换来源暂停状态。本地夸克标签说明文件须先由官方客户端下载到输入目录；历史其他客户端保留原标签与本地身份，继续人工确认。

| 目录结果 | 含义与处理 |
| --- | --- |
| 已核验 | 当前授权根的身份与所需权限通过检查；不代表其中的视频已下载完整或允许自动整理 |
| 不可用 | 原目录／原卷身份或访问检查失败；权限不足单独标识。恢复原磁盘、目录和权限后重查，不能认领同名替代目录 |
| 未核验 | 当前根授权尚未恢复、检查期间授权更新，或来源关联需重新核对。显示对应修复动作，不将其推断成文件删除 |

schema v25 的 `source_rule_local_health` 保存最近一次完整检查，绑定来源有效版本及生命周期。两侧均完成实际检查时持久化结果；缺少当前授权时，返回「未核验」及同版本的上次完整结果，不用等待状态覆盖原失败，也不把旧结果当作新进程的可用证明。页面将历史结果折叠并明确标记；配置或生命周期不同则不沿用。

文件系统检查只读，诊断写入只发生在 Core SQLite。公开参数不能提供路径、卷授权或自动开关。当前 Core 的十秒短缓存减少重复读取，手动重查绕过缓存；同一来源版本的在途请求仍合并，最多 32 项在途检查，缓存最多 1000 项。配置变化、删除或停止使迟到结果失效，停止等待在途读取后才释放根资源。Renderer 只为当前页本地来源维护十秒轮询，离页或翻页释放旧检查等待，返回后重新查询；操作错误与检查错误分别显示。

恢复健康不会解除来源或全局整理暂停。原卷重新挂载后若旧句柄失效，须由宿主重新核验授权；可编辑来源，重新选择原目录并预览确认。就绪观察和人工确认仍独立执行，健康检查不会启用自动接入。来源编辑已提供自动策略开关及首次真实 COPY 预览授权；当前本地客户端仍降级为人工，7.3 的完整客户端规则与自动权限验收保持未勾选。

2026-10-26 本地健康阶段全量 796 passed／13 skipped，定向核心／来源页面检查及类型、依赖边界通过。开发构建和最终 arm64 未签名目录包各通过五项窗口检查，覆盖原输入／目标被同名目录替换、目标权限撤销与恢复、暂停中重查、Core 重启后的历史诊断、Renderer 重载及受控宿主恢复；来源 ID、版本、暂停、原文件内容和 inode 保留，没有新候选或文件作业。目录对话框与 resume 事件为受控入口，实际目录改名、权限与文件检查使用真实临时目录，不作为真实磁盘拔插、系统选择器、休眠或客户端完成规则的证据。v24 → v25 迁移验证原配置、历史客户端标签、任务、外键、备份和失败回滚，旧核心拒绝新库。源码、ASAR 和三张实际窗口截图摘要见 `tools/desktop-files/fixtures/mac-local-source-health-2026-10-26.json`。

## 持久手动补扫

「待处理 → 补扫本地文件」登记扫描意图后立即返回作业 ID，不在页面请求里等待目录枚举。固定 `ingestion.scan` 只接受已有来源 ID 和请求键；`ingestion.scans` 每页最多二十五项，`ingestion.scan-job` 每页最多一百条文件问题，不接受任意路径、授权或自动整理参数。重复请求键返回原收据，同一来源、有效配置和生命周期的并发点击合并为同一未完成作业。已完成后新请求建立新记录，保留原问题供核对。

schema v26 的 `ingestion_source_scan`、`ingestion_source_scan_request` 和 `ingestion_source_scan_issue` 保存冻结来源身份、物理来源版本、请求收据及结果。`SourceRules` 唯一持有扫描所有者，启动和每十秒推进最多四个作业，共用 `IngestionPipeline.scan` 的来源内在途合并，不绕过候选、忽略或就绪检查，也不发起识别、COPY 或下载。现有自动目录补扫仍使用同一扫描原语，不由页面重复创建作业。共享下载根的实际扫描可合并，但网盘扫描摘要只汇总本来源当前版本的有效需求；其他来源的数量和读取问题不会归入此记录。

作业状态为 PENDING、RUNNING、WAITING_SOURCE、COMPLETED、PARTIAL_FAILED 或 FAILED。完整枚举前不显示虚构总量或百分比；完成数量是本次核对的媒体候选项数量，包含既有候选，不代表新增文件数。单文件或字幕读取失败保留相对路径、可信原因和修复动作，其他文件继续，含失败的扫描不能显示为完成。根目录枚举失败不将已知文件视为删除。

受管下载目录中的既有完成项也会在每次补扫时检查实际文件可读性。即使候选已处理或旧版本已淘汰，幂等接收回执也不能单独计为本次文件核对成功；权限撤销、文件缺失或替换造成的访问失败仍进入逐项问题，并按当前来源的有效需求过滤。下载交接的幂等回执继续可在暂停或缺盘时补记，补记与实际补扫采用不同的成功依据。

来源或全局整理暂停、缺少原授权时，作业保存 WAITING_SOURCE 和原因。扫描读取及返回后重新核对暂停、授权对象与规则版本；暂停信号进入目录枚举，迟到属性读取不能新增候选或更新稳定观察。原目录恢复后重新枚举，已发现候选保留，仍需至少一百二十秒稳定观察和人工确认。配置或删除生命周期变化使旧意图失败，不能将同一作业改用新目录或新版本；重新发起将建立新记录。

关闭页面只释放轮询与视图订阅，不取消后台补扫。Core 停止先禁止新意图并中断扫描，在途枚举落定后将未完成工作保留为 PENDING，再关闭数据库；重启将遗留 RUNNING 恢复为 PENDING，并等待宿主重验原目录。页面、轮询和重新挂载只查询已有记录。响应丢失后重试沿用请求键，不能将请求超时解释为扫描或文件操作已撤销。

## 旧配置迁移与恢复

schema v9 建立来源聚合，v10 在单个事务中追加旧身份的映射。普通本地来源沿用原 ID、客户端标签、路径、版本和暂停状态；订阅沿用原 ID、账号、远端引用、下载授权、过滤与周期，暂停状态独立保留。未确认的订阅仍是未启用草稿，重新预览后可复用原订阅 ID。已经存在的有效来源不重复创建；升级前尚未确认的新草稿保留其编辑内容。

迁移不修改原来源、订阅、扫描、下载作业、共享需求、候选、文件操作计划或磁盘文件，也不启动扫描。一次性历史仅登记为历史引用，不生成来源或订阅。同根多个订阅、未知整理绑定和不完整的历史配置均保留为待核对；不能从下载根推定某次下载的整理意图。缺少原版本快照的历史作业保留定位证据，不伪造配置版本；仅能证明下载范围、不能证明整理意图的记录另有 `review_required` 标记。

`source_rule_legacy_reference` 保存旧入口类型、原 ID、来源 ID（可为空）、状态及固定原因。`source-rules.resolve-legacy` 定位旧本地来源、订阅、受管绑定或下载作业；无法唯一定位时返回待核对状态。`source-rules.legacy` 按状态分页查询，供统一来源入口展示和人工核对。确认来源后更新其本地／订阅入口映射；旧历史证据不会因此被改写为已确认。

每次升级前保存一致性 SQLite 备份 `<数据库>.before-v<目标版本>.bak`。单步失败回滚该步结构和数据，保留已完成的前序迁移；重启从当前 schema 继续，不重复生成配置或作业。重试发现原备份时保留它，另写带原 schema 和随机 ID 的备份，不覆盖最初恢复点。

需要整包回退时使用设置或应用菜单中的「恢复升级备份」，恢复匹配快照后安装对应版本；其流程同时核对数据库与凭据文件。数据库旁的迁移备份只用于核对和受控恢复，不能代替整套私有快照。旧 Core 会拒绝打开更高版本数据库，不能直接降级运行。媒体文件不在私有备份中，恢复后仍按既有证据核对流程处理。

## 执行与暂停

schema v11 增加来源控制收据、一次性执行意图及暂停作业归属。`source-rules.run-once` 只接受有效来源版本；重复请求返回同一意图，同时触发合并为一轮。Core 完整枚举已确认范围后创建下载需求，不创建或启用周期订阅。范围预览、空范围、失败和废弃分别记账；`SUBMITTED` 仅表示已提交下载需求，不代表下载、整理或 Emby 收录完成。活动周期扫描或同版本作业可以被复用。

一次性意图先落库，进程退出后继续相同意图。半完成的枚举重新生成预览；确认已提交但执行收据尚未更新时，先按预览关联原作业。来源配置版本变化使旧意图废弃；来源暂停、账号或原目录尚未恢复时保留等待，网络枚举失败需要显式重新执行，不无限重试。

`source-rules.control` 提供 `scan`、`pause`、`resume`。立即扫描仅适用于已确认、已恢复且启用周期的目录来源，同版本活动扫描合并；退出期间漏过的周期仍由订阅引擎合并补扫。旧订阅控制不能独立改变统一来源，调度领取和下载确认均核对来源版本、暂停及待核对状态。暂停意图先持久化，启动和主机恢复时协调执行模块，离线不阻止 Core 启动。

| 操作 | 作用范围与恢复 |
| --- | --- |
| 暂停来源 | 停止本来源的新扫描、下载需求及新整理接入；记录此次暂停的活动作业，其他来源需要的共享下载继续 |
| 恢复来源 | 只恢复本来源暂停的同版本需求；全局暂停仍生效，不恢复用户单独暂停或取消的作业 |
| 全局云端暂停 | 停止云端写入和新领取，扫描仍可产生等待需求；全局恢复跳过仍暂停的来源 |
| 全局整理暂停 | `ingestion.set-paused` 独立持久化，停止新识别／整理并协调活动 COPY 的安全点；不更改来源或下载策略 |
| 单项暂停／取消 | 仅改变该任务的需求，不关闭来源周期，不回滚已提交文件，不取消其他有效需求的共享传输 |

来源恢复和全局云端恢复可按任意顺序操作，仍暂停的一层继续阻断领取。暂停过程中的未停止写入不能立即恢复。已经正式提交的文件及其 Emby 交付继续由独立状态机核对，不因来源或整理暂停回滚。

整理执行分别登记候选级取消信号，全局暂停和退出再向各项传播。暂停一个来源只中断所属候选的识别、主文件或附属文件复制，不取消同轮其他来源的工作；共享根按当前有效需求决定同一资产能否继续。已完成主视频的字幕仍在执行时，也属于取消协调范围。附属文件稳定观察按物理来源、整理策略和文件路径区分；暂停只重置失去有效需求的文件，不能因目标相同就重置其他范围。识别被暂停后保留原任务为待识别，未发布 COPY 保留原计划及暂存证据，已正式发布的文件继续完成记账。

显式恢复会立即请求受管补扫，重复控制仍查询原收据，不重放旧控制；全局整理暂停继续阻断扫描和领取。恢复后的主文件和附属文件重新建立稳定窗口，恢复不会创建新的复制计划来替代已领取计划。上述取消与补扫已有隔离文件和真实 SQLite 回归；来源可恢复删除见下节；第 4.6 项的重置范围仍待确认，不据此标为全部完成。

2026-10-25 的该修复全量回归为 496 项通过、13 项条件跳过；4 项定向 Electron 开发构建检查覆盖来源暂停、配置重启、冲突恢复与内容复核。另验证同一共享下载根下的不同目标、相同目标不同文件，以及主视频已记账时的字幕中断与恢复；原媒体 inode 和来源内容保持。类型、依赖边界、构建、文档及 OpenSpec 严格检查通过；没有在个人媒体目录执行暂停、重置或重新复制。

### 可恢复删除

schema v17 为来源增加删除时间及独立的生命周期版本。删除将来源移入「已删除来源」并保持暂停，保留配置快照、候选、下载需求、COPY 计划和任务历史；不删除媒体、账号或密钥。未提交的一次执行意图废弃，未确认预览失效，内容复核取消并保留已完成的逐项结果。已提交的媒体及 Emby 交付继续核对。

确认框列出来源名称、配置版本、输入或下载目录、整理目标，默认焦点为取消。取消与 Escape 不发写命令；未保存的同来源编辑需要先保存或取消。删除后的配置可只读查看，历史列表按页显示。恢复仍保持暂停，用户核对原目录后显式恢复工作；不会解除全局暂停，也不会重放已经废弃的一次执行。

删除前检查实际下载写入和识别／复制执行。需先暂停并等写入停止，停在暂存阶段的持久 COPY 计划可保留，恢复后重新观察并继续同一计划。共享文件仍有其他有效同策略需求时继续原执行，不按共同物理目录取消其他来源。归属不明的旧活动计划阻止删除，并提供任务定位。

删除释放普通本地输入的当前归属，新来源可接管相同路径；恢复旧来源前重新检查重叠。历史媒体目标继续保护，不能作为新输入。原卷身份、目标授权与文件证据保留，不把替代卷当成原目录。暂停或删除的来源不启动目录监听，恢复后重新建立观察窗口。

删除／恢复在单事务保存状态、预览失效、意图处理及请求收据。配置版本不因删除变化；生命周期版本阻止删除又恢复后的旧编辑、控制、执行预览或异步下载确认重新生效。重复请求查询当前状态，不重放旧删除。v16 → v17 迁移保留原来源、任务和外键引用；提交前核对外键，失败整体回滚，并保留升级前备份，旧 Core 拒绝新库。

### 执行预览与界面状态

schema v13 增加独立的执行预览及确认收据。来源卡片的执行一次和强制重下使用 `preview-execution`、`get-execution-preview` 与 `execute`，只读取有效配置，不保存草稿、不更改周期策略。强制模式显示独立完成路径，确认前不产生下载意图；确认后创建或合并同版本同模式意图。普通与强制模式不互相替代，强制模式不会复用普通下载作业或覆盖原成果。

执行确认、意图和幂等收据在同一个短事务中落库。暂停会使未确认预览失效，配置版本变化也会阻止旧预览；确认过的旧意图按已有运行约束暂停或废弃。强制预览过期后要求显式重新预览，不默默扩大为新的未确认范围。旧 Preload 保存／订阅／直接下载编辑方法保留明确的迁移错误，Main 同时拒绝这些旧写入口；底层类的兼容代码仍用于历史恢复与测试，不再提供第二套界面配置。

Renderer 的账号连接模型、来源模型分别持有核心 DTO 和操作反馈。来源输入、未保存标记及远端选择器状态由路由上层的 React `SourceDraftProvider` 唯一持有，返回账号或设置页再回来仍保留；不在 StatefulService 或另一个全局 store 复制表单。来源数量和操作状态通过框架 computed 及选择性订阅读取。

来源的异步查询、分页与选择均核对代际；React effect 和 StrictMode 重挂载只查询，不重放保存、确认或执行。卸载最后一个页面释放轮询，卸载 React 根解除草稿绑定，不停止共享 Application；根重新挂载只读回核心已保存草稿，未保存输入随旧根释放。保存已提交而界面已卸载时保留核心结果，不继续发起后续预览。原生目录权限按用途累加，同文档路由切换不丢失授权，完整重载或窗口关闭会清理临时授权。

## 表单中的文件去向

各开关在标题旁显示当前草稿的运行方式：定期检查关闭时为「手动执行」，整理关闭时为「只下载」，自动整理关闭时为「逐项确认」。关闭整理的说明使用「开启后才进入识别与整理」，不能将尚未启用的行为描述为当前结果。下载时机与整理互不影响：关闭定期检查保留整理设置，关闭整理保留定期检查；相关字段随各自开关显示，底部执行说明同步更新。

来源编辑顶部显示「网盘内容 → 下载到本地 → 可选整理到媒体库」，并随草稿更新所选路径及整理状态。网盘配置按范围、下载位置、下载方式、可选整理四组排列：可选筛选默认收起，已有条件初始展开，收起后仍提示已设置且不清空条件；格式和精确文件名筛选同时生效；周期扫描只展开扫描间隔；开启整理才显示媒体库目标和媒体类型。只下载时不要求 TMDB、媒体目标或 Emby。整理使用 TMDB 识别，默认在待处理页预览并人工确认后 COPY；首次预览授权后可选择满足完整条件的新文件自动整理，保留下载原件；Emby 是复制完成后的独立收录环节。

提交操作前的「当前配置会怎样运行」随周期和整理开关更新，分别说明何时下载与下载完成后的处理。摘要描述草稿确认后的行为，修改选项本身不提交任务。操作说明与当前窗口截图见[来源、下载与整理内测](../product/cloud-downloads.md#看懂来源配置)。

开关使用「定期检查网盘目录」和「下载后整理到媒体库」，分别对应网盘增量下载与本地文件整理。开启整理后，默认先在「待处理」核对作品、季集及目标并确认。另一个「自动整理满足条件的新文件」开关需要真实首次预览与明确接受；仅开启整理或保存草稿不授权自动复制。自动意图、当前本地降级及共享权限待决边界见[识别与自动意图](./desktop-recognition.md#自动整理意图与共享季集校验)。

## 下载需求与整理策略

schema v12 为候选追加不可修改的 `ingestion_candidate_policy`。受管下载根对应的物理 `ingestion_source` 仅负责原卷授权、读取和补扫；来源的有效版本分别保存整理目标授权。新增共享来源不修改物理来源版本或覆盖其他来源的整理目标，用户无需为完成目录新建普通本地来源。

`resolveManagedOrganization` 读取完成项关联的下载需求、其来源版本和有效状态。未启用整理的来源不产生整理候选；其他有效来源仍可为同一共享项提出整理需求。相同策略复用唯一 item/version 候选及其策略快照，根目录本身不作为归属证据。历史缺少快照、归属不明或来源配置已变化的需求保持待核对，不套用当前策略。尚未接入统一来源的旧调用保留受限兼容；已经迁移的历史不能通过兼容入口重新认领。

确认预览按远端目录层级及过滤比较有效来源：相同策略可共享，互不相交的范围或过滤可在同根使用不同目标，重叠范围的不同策略返回冲突来源 ID 和名称并阻止确认。候选识别、预览、确认、主文件与附属文件 COPY 都沿候选快照选择目标，不受另一来源或全局默认路由覆盖。已经持久化且开始执行的旧人工确认操作可沿原计划及验证证据恢复到安全点，不据此创建新的未知归属候选。

outbox 与 completed 补扫使用同一个接收端。只下载、暂停及待核对状态在投递前阻断，不消耗投递重试预算，也不伪造接收确认。确认事务丢失时复用原候选；重复接收仍继续相同文件的稳定观察，暂停期间不累计观察时间。补扫只读取已记账完成项，不遍历认领 completed 内的外部文件；附属文件还需有同策略的受管下载证据。

Main 分别恢复每个已登记媒体目标和受管读取来源。额外目标的授权通过私有 bootstrap／authorize 动作重新核对原卷，不依赖物理来源最初绑定的目标在线；一个目标缺盘不会阻断同根的其他策略。来源暂停仅重置失去有效整理需求的候选，仍有其他来源需要的共享候选继续观察。

下载任务 DTO 携带来源 ID／版本，以及未启用整理、已启用、待核对或未归属状态。只下载任务不会显示成待入库或借用其他来源的整理计数。媒体目标查询包括来源当前使用的目标和等待交付的历史目标，按授权 ID 去重，供已有 Emby 服务器映射使用。COPY 完成后保留来源文件并单独建立 Emby 待交付记录；真实服务器的收录仍须由 9.4 验收。

## 本地发现与忽略

schema v14 在本地来源的不可变 JSON 配置中追加 `ignoredFilePatterns`，不重写升级前的草稿、版本、目录或暂停状态。未提供／null 使用系统默认，显式空列表关闭可配置忽略，自定义列表替换默认规则；配置仍须保存、预览、确认后才改变扫描。升级前的一致性备份保留 v13 原文，v13 核心拒绝打开 v14，避免旧实现误读新字段。网盘配置不接受该字段，远端范围仍沿用独立下载过滤。

默认规则沿用旧发现服务，忽略隐藏项、常见临时文件、系统索引和任意层级的 sample／samples 目录。文件名使用大小写不敏感的 glob，目录名规则以 `/` 结尾并剪枝整个子树；空列表不会绕过应用私有目录排除、符号链接限制或就绪检查。样片规则独立：仅在同目录存在精确同基名的主视频时，才跳过 `.sample`、`-sample` 或 `_sample` 后缀视频；独立的 Sample Movie 不因此被忽略。

启动、每十秒、事件合并及手动补扫共用候选接收。事件不直接创建识别或 COPY，监听不可用时继续定时补扫。已知候选即使没有新事件也复核；不可读或临时改名导致的缺失保留为不可用，不删除原证据。零字节、变化中的版本和下载临时名称均不能就绪，正式改名后从头计算稳定窗口。已观察到的夸克 `.qkdownloading` 名称仅作为等待证据，尚未完成的官方客户端行为矩阵不据此开放自动接入。

普通扫描无法保证发现同属性的内容替换。本地来源可在待处理页显式发起全量内容复核，保留持久进度及逐项失败；新内容版本重新观察，原任务及已整理文件保留。首次无摘要的文件只建立基线，具体版本约束、取消与恢复见[本地资产版本与全量内容复核](./desktop-ingestion.md#本地资产版本与全量内容复核)。

## 本地目录授权与失联恢复

来源与目标相同、互为祖先后代，或与其他活动来源及历史目标交叉时，确认阶段拒绝启用。冲突信息从 Core 的已登记配置生成，包含原来源名称和来源 ID；涉及受管下载根或历史媒体目标时给出对应授权 ID，不从磁盘管理标记猜归属。独立输入可复用同一既有媒体目标授权；来源根、子目录和文件符号链接不能绕过真实路径核验。COPY 是契约允许的唯一操作。

原目录不可访问时，保留候选、任务与已执行计划，不创建同名替代根或删除历史。扫描记录来源健康不可用，并清空该来源主文件及附属文件的观察时钟；即使只中断十秒，也不能继续沿用之前的 READY。恢复同一原目录后重新建立完整稳定窗口，同名替代目录仍因目录／卷身份不符被拒绝；新卷必须经原生授权复核。

真实临时目录用例覆盖相同路径、双向包含、跨规则相同／父子目录、共用合法目标、根及子路径符号链接、权限撤销、目录失联和同名替代目录，均保留原文件与配置。真实窗口验证重复来源的错误可定位原规则，修改输入目录后重新预览和确认才生效；不把草稿修正当作媒体操作。

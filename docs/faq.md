# Media Marshal 常见问题

> 按 2026-09-05 的 v0.2.13.1 工作区能力整理。安装与升级步骤见[部署指南](./deployment.md)，具体操作见[用户手册](./user-guide.md)。

## 文件发现

### 为什么没有自动识别到新文件？

先检查规则是否启用、源目录是否在后端容器内可见、文件是否仍在写入，再检查忽略规则和 Sample 检测。源路径已有有效任务时也会去重，不会每次扫描都新建记录。可先执行一次手动全量扫描。

### 为什么手动扫描能发现，实时监听没有发现？

NAS、网络盘和容器挂载可能没有传递完整的文件事件。建议使用混合模式，用周期扫描补偿；默认 10 分钟，最短 5 分钟。当前没有完整扫描进度页，扫描请求成功不代表所有媒体已经处理结束。

### Docker 页面中为什么找不到宿主机目录？

目录浏览显示后端容器的文件系统。当前三份 Compose 都把 `MEDIA_DIRS` 指向的宿主机目录挂到 `/media`；例如宿主机 `/srv/media/Downloads` 对应容器 `/media/Downloads`。alpha 与其他部署方式的数据目录来源不同，详见部署指南。

### 为什么文件没有任务记录，另一些却显示“已跳过”？

命中忽略规则、默认 Sample 目录或高置信度 Sample 视频检测的文件会静默忽略。未被忽略但不参与整理的内容会按发现规则记录 `SKIPPED` 和原因。ISO、剧集蓝光、裸 `sourceDir/BDMV` 当前不支持整理。

### Sample 会不会误删正片？

Sample 检测只在发现阶段跳过，不删除文件。默认剪枝 `sample/`、`samples/`；同目录视频检测要求独立 `.sample`、`-sample`、`_sample` 后缀，并存在同 basename 对应正片。自定义忽略列表不会被自动覆盖；可在页面合并缺失的 Sample 规则。

## 识别与确认

### 为什么任务进入待确认队列？

通常是匹配置信度不足或没有明确候选。可编辑识别信息、重新匹配，或全局搜索 TMDB 后选择正确条目。低置信度保护不等于所有解析异常都会进入 Queue；当前部分解析异常仍显示失败。

### 中文、双语或同名不同年份的内容识别错误怎么办？

检查解析标题、年份和媒体类型，剧集还需核对季集。系统已有多 Query 和父目录辅助，但仍可能误判。待确认任务在 Queue 编辑 / 搜索；已经完成的任务在 Dashboard 使用“修正”，基于当前目标资产生成预览。

### 连续多集与离散集号都支持吗？

支持 `E16-E17` 这类连续范围。类似 `[1,2,9]` 的非连续解析列表当前会被拒绝，不会自动当成 `1～9` 或只取第一集。歧义分类、人工修复入口和确定性错误重试抑制仍待补齐。

### 为什么同一个文件的失败次数一直增加？

失败记录会按源路径、规则和错误码聚合，但失败状态不会阻止再次扫描处理。文件或环境未改变时，相同问题可能再次出现。先检查错误原因；不要把失败聚合当作自动修复或退避重试机制。

### Queue 批量编辑和已完成剧集批量修正有什么区别？

| 入口 | 对象 | 范围与行为 |
|---|---|---|
| Queue 批量编辑 / 确认 | 待确认普通视频 | 当前页选中任务；编辑公共字段、顺序集号或选择候选 |
| Dashboard 同季 / 同剧集修正 | 已完成普通视频剧集 | 后端跨分页查询同规则、当前 TMDB 的有效任务；预览并移动目标库资产 |

同季 / 同剧集修正保留每条任务的原季集，不把所有分集改成同一个集号。预览可排除任务；选中项存在阻断时不能创建作业。

### 关闭浏览器后批量修正会停止吗？

不会因关闭弹窗或浏览器取消后台作业。当前同一浏览器保留最近 30 天内的任务与批次关联，可从相关任务再次进入。换浏览器或清缓存后，页面暂不能检索全部历史作业。

查询进度遇到网络错误可能停止刷新，可重新进入查看。服务重启会将未结束作业标为中断；先核对错误及人工恢复路径，再重试失败项。已成功项不会重复执行，不支持整批自动回滚。

## 文件整理与 NFO

### 为什么提示目标冲突而不自动覆盖？

系统保护已有文件，不覆盖、不合并、不自动添加后缀。先核对目标是否为同一资源，再由用户处理冲突或调整模板；已完成任务修正还会检查附属文件和批次内部冲突。

### 为什么硬链接或符号链接失败？

硬链接要求同一文件系统且支持该能力；跨磁盘、跨挂载、权限不足均可能失败。符号链接需要权限，并且媒体服务器能解析链接中的目标路径。当前不会静默改为复制；先检查挂载与能力预检结果。

### 附属文件和已有 NFO 怎么处理？

普通视频按规则处理同名字幕、NFO、封面和 `.md5` 等；MD5 文件仅跟随移动 / 改名，不修改内部内容。Media Marshal 不再生成或重新生成 NFO，元数据刮削及 NFO 保存交给 Emby 等媒体服务器。用户已有的 NFO 仍可作为附属文件跟随整理。

修正中的 `poster.jpg`、`folder.jpg`、`cover.jpg`、剧集共享封面或 `tvshow.nfo` 不自动跟随批量移动。电影蓝光目录内部文件随目录整体处理，根目录外旁挂文件不在当前支持范围内。

### 主视频已整理，但字幕或 NFO 异常怎么办？

先核对实际目标文件与后端日志。附属项失败目前还没有完整的独立任务详情和重试闭环，不能仅看主任务状态断定所有附属项成功，也不要直接重复运行整条任务来猜测修复结果。

### 删除任务记录会删除媒体吗？

不会直接删除媒体文件，只删除任务及候选记录；可能使修正历史关联无法继续查看。删除有效任务记录后，源文件仍在时后续扫描可能重新发现它。当前删除 / 规则变更 / 重置尚未与所有活跃文件作业统一互斥，应等待整理和修正结束再操作。

## 系统与网络

### 保存配置后为什么似乎没生效？

API Key 仅由 Web UI 保存到数据库；普通配置采用环境变量 > application 配置 > 数据库；TMDB 代理则以 Web UI 显式保存为优先。页面保存值可能被高优先级配置覆盖。编辑 `.env` 不会自动更新已经运行的容器。

### 配置代理后为什么仍无法搜索或显示海报？

使用后端容器可达的 HTTP 代理地址，不能把宿主机的 `127.0.0.1` 当成容器可达地址。当前代理仅作用于 TMDB API，不代理浏览器加载的海报；不支持 SOCKS、HTTPS 类型代理或代理认证。还需核对 API Key、代理实际生效来源和缓存。

### 支持 Webhook、邮件通知和用户认证吗？

Webhook 只有预留字段，没有可用通知接口。邮件后端保留发送逻辑和配置，但页面禁用，完整投递流程尚待验收。应用没有内置用户认证，建议在本机、可信内网或 VPN 内部署；只保护前端入口还不够，后端直连端口也需受控。

### SQLite 在哪里，路径导出能当备份吗？

数据库位于后端 `/data/media-marshal.db`。路径规则导出不包含任务、候选、全局设置或批次，不能替代数据库备份。停止服务后备份完整 `/data`，保留配套版本和部署配置，在隔离环境验证恢复。

### 升级失败能否只换回旧镜像？

不能保证。数据库可能已经迁移，应使用配套旧版本与升级前数据库。数据库回滚也不会撤销已执行的媒体移动。具体流程和验证边界见[部署指南](./deployment.md)。

# 内置传输运行环境

## Purpose

让用户只安装桌面应用即可运行所需网盘接入与文件传输组件，并将其权限、凭据、生命周期和版本纳入统一管理。组件故障或升级不得产生重复写入者、泄露授权信息，也不得损坏用户已经下载及整理的文件。

## ADDED Requirements

### Requirement: Mac 优先交付与平台扩展

本变更当前 SHALL 只交付同一个 macOS 客户端，优先完成 Apple Silicon 上的功能闭环，并为实际通过验收的 Mac 架构提供安装包。Windows 等其他平台 SHALL 保留宿主策略、资源解析与契约兼容的扩展空间，MUST 不作为本轮 Mac 功能或内测交付前置。平台差异 MUST 不进入云端业务状态机、业务标识或公开 DTO；未验收平台不得宣传为已支持。

#### Scenario: Mac 功能完成但其他平台尚未交付
- **WHEN** Mac 账号、下载与安装态检查通过，而 Windows 客户端或安装器尚未完成
- **THEN** 可以交付明确标识状态的 Mac 内测包，不要求补齐 Windows；保留既有兼容实现及测试结果，正式公开发行仍需满足 Mac 签名和公证要求

### Requirement: 自包含安装与组件完整性

当前 Mac 安装包 SHALL 按其 macOS arm64 或 macOS x64 架构随包提供经过固定版本和完整性验证的 OpenList、Rclone；不得混入其他平台资源。用户 MUST 无需另装这些工具、Docker 或开发环境。缺少资源、架构不匹配或完整性失败时 MUST 禁用云端操作并解释原因，不从系统 PATH 或未知地址自动寻找替代程序。已有 Windows 资源清单 SHALL 保留为后续平台适配材料，不构成本轮 Windows 发行承诺。

#### Scenario: 干净系统启动
- **WHEN** 用户在受支持的无开发环境系统安装应用并配置云端来源
- **THEN** 应用使用包内匹配架构的组件完成初始化，配置和可变数据写入用户数据目录而非安装目录

### Requirement: 内部服务隔离与授权

新增服务 MUST 仅监听受控回环地址，使用随机强凭据，并拒绝未授权访问。界面 MUST 只调用经过校验的业务动作，不获得管理密钥、任意 HTTP 代理、命令执行或本地文件读写能力。端口被占用时 SHALL 有限重选，不复用未知服务。

#### Scenario: 端口被其他进程占用
- **WHEN** 组件启动时选定端口已被占用
- **THEN** 应用识别绑定失败并重新选择端口，验证新实例身份与授权后才发送账号信息，不因收到 HTTP 成功响应就信任占用者

#### Scenario: 本地非授权客户端访问
- **WHEN** 浏览器页面或其他未持有授权的客户端访问内部目录和管理接口
- **THEN** 请求不能读取账号、网盘目录或控制任务；Renderer 也不能借业务 IPC 注入任意地址与命令

### Requirement: 凭据保存与组件私有数据

应用 MUST 通过系统凭据保护保存权威凭据，业务数据库、进程参数、普通响应、默认诊断和日志不得包含原始凭据。组件确需使用的私有明文状态 SHALL 限制为当前用户可访问，并从普通备份和诊断排除；应用 MUST 如实说明该例外，不宣称所有组件数据均已加密。

#### Scenario: 导出诊断或备份业务数据
- **WHEN** 用户导出默认诊断或普通业务备份
- **THEN** 不包含 Cookie、管理密钥、传输密钥、临时签名地址、组件原始数据库或未脱敏个人路径

#### Scenario: 系统加密能力不可用
- **WHEN** 保存账号时系统凭据保护不可用
- **THEN** 应用拒绝持久保存并给出可重试错误，不降级为业务配置明文

### Requirement: 进程生命周期与异常回收

云端能力启用后 OpenList SHALL 在应用后台期间保持可用，传输进程 SHALL 按受控任务启动。关闭窗口不等于退出；显式退出 MUST 先停止领取、结束传输、记账，再关闭依赖。Main、核心或组件宿主异常时 MUST 撤销旧执行权限，在确认旧写入者停止之前不得启动替代执行。

#### Scenario: Main 被强制结束
- **WHEN** Main 进程异常终止而下载仍在进行
- **THEN** 受管宿主检测父连接失效并终止自有传输及网盘进程；下次启动先核对旧实例，未确认退出则阻止新写入

#### Scenario: 媒体核心崩溃
- **WHEN** 业务数据库所有者退出而传输仍在进行
- **THEN** 宿主停止旧核心代际的传输，保留核对证据；新核心不得在旧写入者未停止时恢复领取

### Requirement: 就绪检查与有限恢复

服务就绪 MUST 同时满足版本兼容、受控实例、授权可用和必要接入能力；单纯端口可达不得等同就绪。启动和自动恢复 SHALL 有次数与时间上限，失败时保留诊断、提供重试，且不阻塞普通本地目录功能。

#### Scenario: OpenList 反复启动失败
- **WHEN** 启动超时或恢复预算耗尽
- **THEN** 云端来源显示组件不可用并停止新领取，本地任务与历史仍可查询，不无限重启或重放业务写操作

### Requirement: 版本升级与发行追踪

组件 SHALL 随应用整包升级，禁止运行时自行更新。升级前 MUST 停止写入并备份兼容性所需数据；降级必须使用匹配版本及备份。正式公开发行的 Mac 包 SHALL 验证开发者签名、公证及嵌套二进制，并附组件版本、许可、来源及相应源码获取材料。未签名内测 SHALL 明确标识，不得作为正式发行完成的证据；当前无签名配置时该发行项 MUST 保持未完成。

#### Scenario: 新组件升级失败
- **WHEN** 组件或数据迁移失败
- **THEN** 应用停止云端写入并保留旧备份，不让旧组件直接打开不兼容的新库；已下载媒体保持不变

#### Scenario: 卸载与重新安装
- **WHEN** 用户卸载后重新安装应用
- **THEN** 默认不删除下载文件、媒体库或用户任务数据，重新授权或恢复配置后可核对既有成果

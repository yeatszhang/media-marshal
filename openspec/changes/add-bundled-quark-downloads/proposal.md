# 内置网盘下载与可替换适配器提案

## 为什么

Media Marshal 现有桌面规划依赖用户先用网盘客户端下载文件，再接入本地整理。新增内置 OpenList 与 Rclone，让用户在一个应用中完成夸克账号配置、目录浏览、自动下载和后续入库，同时把网盘实现隔离在可替换边界内，避免未来自研适配器时重写任务、界面和整理流程。

## 变更内容

- 当前只交付一个 macOS 客户端，沿用同一应用、代码库和业务协议。开发及真实账号闭环优先在 Apple Silicon 完成，保留 macOS Intel 的同产品架构适配；Mac 分发按实际验证的架构提供安装包。Windows 等其他平台只保留扩展边界、资源映射和兼容测试，不作为本轮功能或安装验收门槛。
- 采用进程级集成：随安装包分发 OpenList、Rclone；启用云端来源后 OpenList 常驻，Rclone 按传输批次启动 CLI。无需用户安装这两个工具或 Docker。
- 首版支持夸克普通 Cookie 驱动、目录浏览、一次性下载、周期目录订阅、增量复制、任务进度、暂停、取消和失败重试。登录配置明确为用户提供自己的 Cookie，不把扫码登录或官方开放授权列为已具备能力。
- 增加 `CloudDriveProvider`、`TransferSourceLease` 和 `TransferEngine` 三个边界。业务层使用应用自己的账号、远端节点、订阅和任务 ID；OpenList 挂载 ID、WebDAV 地址和 Rclone 参数只存在于基础设施层。
- 应用负责扫描、增量判定、调度、持久化和完成核对；Rclone 负责字节传输及有限重试。首版不使用 `sync`、不删除云端文件或同步删除本地文件，不把 `--size-only` 当作可靠版本判断。
- 下载先进入受管暂存区，校验并提交后产生幂等的本地接入意图；沿用既有识别、确认、COPY 整理和 Emby 交付边界。下载完成、整理完成、Emby 收录分别展示。
- Main 管理二进制、凭据和进程生命周期，Utility Process 继续独占业务 SQLite；只允许内部回环 API，Renderer 使用受限业务 IPC。
- 保留普通本地目录接入。为自研夸克适配器提供静态注册、能力声明、契约测试、逐账号迁移和回退路径；本次不实现自研夸克协议或通用插件市场。

## 能力

### 新增能力

- `cloud-drive-access`：账号授权、远端目录与节点、能力声明、可替换网盘适配器及迁移边界。
- `managed-cloud-downloads`：目录订阅、增量计划、传输状态、恢复、文件提交及本地整理交接。
- `bundled-transfer-runtime`：随包组件、回环服务、凭据隔离、进程监管、平台分发与升级。

### 修改能力

当前 `openspec/specs/` 为空，无已归档主规格可修改。本变更依赖在途变更 `add-local-desktop-emby-ingestion` 的桌面运行基础；不重复定义它的媒体整理与 Emby 规则。

本变更扩展前案的产品范围：前案中“不登录网盘、不控制下载”“无内部 HTTP 服务”“必须另装网盘客户端”等排除项，在新增的受管云端来源上由本提案取代；普通本地目录来源继续适用原约束。实施和归档时必须按 `design.md` 的兼容关系协调两份规划，不能把互相矛盾的全局要求同时归入主规格。

## 影响

- 沿用 `apps/desktop`、`packages/contracts`、`packages/media-core` 和 `@yeatz/app-framework`；新增内部云端契约、Main 网盘/进程模块、Core 下载模块与 React 页面。
- 为业务 SQLite 增加账号引用、实现绑定、订阅、扫描记录、远端条目、下载项、执行尝试和接入意图；OpenList 私有数据库独立存放，不作为应用业务事实来源。
- 扩展 `apps/desktop/electron-builder.yml` 和发行检查，当前准备及分发 macOS arm64/x64 对应资源。已有 Windows x64 的锁定资产及兼容实现保留，实际 Windows 客户端与安装器留待后续平台变更。沿用手动整包升级，不在运行时自更新组件。
- 当前代码仅有桌面骨架、来源 CRUD 和基础持久化，核心仍报告 `manual-only`、解析器 `unavailable`；本方案不将规划中的完整整理流水线当作已实现依赖。下载可独立验收，自动入库闭环须等待前案相关能力交付。
- 上游夸克驱动兼容性、凭据落盘、平台退出清理和真实大文件传输列为实施前置验证；不承诺突破会员限速、稳定直链或跨进程字节级续传。

## 本轮交付优先级

先完成 Mac 上的账号配置 → 目录浏览 → 预览 → 完整文件下载 → 校验提交 → 暂停/恢复与失败处理，并交付可验证的 Mac 内测包；随后推进目录订阅和整理交接。平台策略与 Provider/Engine 边界保持独立，既不为 Mac 首发写死业务协议，也不提前实现其他平台客户端。

已有三目标组件/宿主验收结果作为历史证据保留，不再要求每项新功能同步完成 Windows 验收。未签名 Mac 内测、功能验收和公开发行分别记录；当前没有签名配置，正式签名/公证项继续保持未完成，不阻塞 Mac 功能开发。

# Spec Delta

## ADDED Requirements

### Requirement: 逐文件提交核对与异常恢复

系统 SHALL 分页提供下载异常文件的相对路径、阶段、可信原因及修复动作，区分部分异常与其他文件仍在传输。用户 SHALL 能逐文件重新核对已停止的原提交；命令 MUST 合并重复执行，且只根据原卷、文件身份、大小、摘要、停止证据及提交意图补齐完成事务、同步收据和交接事件，不得启动新的传输。不同目标的同账号活动传输 SHALL 不阻塞安全核对；同条目活动写入、目标重叠或停止证据不足 MUST 阻断并说明原因。失败 MUST 持久可查且自动重试有退避，暂停与取消不绕过文件提交安全边界。

#### Scenario: 文件已发布但尚未记账
- **WHEN** 原 attempt 已停止，正式文件身份与原证据完全一致，用户触发核对或自动恢复
- **THEN** 幂等补齐完成、收据及交接事件，不重新下载；同账号其他目标的传输可以继续

#### Scenario: 只有原暂存文件完整
- **WHEN** 完成位置为空，原停止证据、暂存文件及提交意图可核验
- **THEN** 继续不覆盖发布并完成记账，重复核对只产生一次完成事实

#### Scenario: 文件冲突或旧写入者不明确
- **WHEN** 目标被外部文件占用、文件校验期间变化、证据不符或停止证据不足
- **THEN** 保留文件、claim 和提交意图，展示具体条目、已知原因及处理指引；未知原因不得猜测为目标占用，不能通过重试下载绕过核对

#### Scenario: 失败、刷新与重启
- **WHEN** 核对失败后刷新页面或重启 Core
- **THEN** 失败仍可查看并再次核对，自动核对有退避；页面展示全部异常的分页入口，成功后移除已解决异常且更新完成计数

# 非 macOS 平台支持

## Purpose

为 Windows、Linux 等非 macOS 用户提供与既有桌面业务一致、可独立验证的客户端，明确支持系统和架构、运行依赖、宿主行为与发行边界，避免将底层兼容试验误当作完整产品支持。

## ADDED Requirements

### Requirement: 按平台声明可用客户端

应用 SHALL 为每个拟交付的非 macOS 系统记录最低版本、架构、安装格式和已验证文件系统。仅完成底层兼容测试的系统 MUST 不展示为可用客户端；各平台可独立发布，Mac 无需等待。

#### Scenario: Windows 已验收但 Linux 未验收
- **WHEN** Windows 安装态和完整业务链路已通过，Linux 仅有构建或单元测试结果
- **THEN** 下载页只将 Windows 列为已支持的新增平台，明确 Linux 尚未交付，不改变 Mac 的发行状态

### Requirement: 自包含原生资源与凭据保护

每个平台安装包 SHALL 包含匹配架构的 SQLite、解析器及受管下载组件，无需系统开发环境。系统凭据保护不可用或资源校验失败时 MUST 阻断依赖该能力的操作并说明原因，不降级为明文保存或使用未知可执行程序。

#### Scenario: 干净系统安装
- **WHEN** 用户在支持矩阵中的无 Java、Node、Python 环境安装客户端
- **THEN** 包内组件可运行，凭据受系统机制保护，配置写入用户数据目录；缺少必要能力时提供明确修复入口

### Requirement: 非 macOS 宿主与文件安全

非 macOS 客户端 SHALL 保持来源、下载、整理和交付的既有业务语义，并验证平台目录授权、卷身份、命名冲突、不覆盖提交、后台运行及异常退出回收。不能证明旧写入者已停止或文件系统支持安全提交时 MUST 阻断新写入。

#### Scenario: 主进程强杀后恢复
- **WHEN** 平台客户端在下载或复制期间被强杀并重新启动
- **THEN** 旧写入者被核实停止后才恢复任务，不重复提交、不覆盖既有文件，媒体和持久化历史可核对

#### Scenario: 路径替换或不可写卷
- **WHEN** 来源或目标被链接替换、原卷缺失，或目标卷不能安全提交
- **THEN** 相关操作阻断并说明原因，不在同名替代路径继续写入

### Requirement: 安装升级与发布证据

非 macOS 客户端 SHALL 按目标系统验证安装、只读安装位置、手动升级、备份恢复和保留数据卸载；正式发行须通过对应产物完整性及签名策略验收。测试包、正式包及历史构建证据 MUST 分开记录。

#### Scenario: 卸载后安装兼容版本
- **WHEN** 用户卸载客户端并重新安装兼容版本
- **THEN** 来源、目标媒体和用户数据保持，客户端可恢复原配置与历史，不将卸载等同于删除媒体

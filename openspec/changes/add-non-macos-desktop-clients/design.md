# 非 macOS 客户端设计

## 上下文

范围见 [proposal.md](proposal.md)。仓库已有 `electron-builder.yml` 的 Windows x64/NSIS 配置、win32 资源映射、Guardian Job Object 与权限测试；没有据此证明当前完整用户流程已在非 macOS 上验收。主变更保留这些基础，本变更只在后续排期后推进。

## 目标与非目标

复用现有 Electron、React、TypeScript Core 和受限 IPC，补齐各目标系统的宿主与发行能力。Mac Intel、Emby 自动安装、多语言和跨系统配置搬迁不在此变更。Windows x64 优先复核；Linux 独立形成支持矩阵，未选定并验收的发行版不承诺支持。

## 决策

- 保持业务状态机和身份契约共用，仅由宿主策略处理凭据、进程树、卷和目录语义。避免为每个平台复制一套下载与整理业务。
- 沿用 Windows 资源和 NSIS 基础，重新验证当前构建；Linux 需要新增资源、系统凭据保护和安装集成。具体最低系统、Linux 发行版及包格式在该变更启动时根据实际依赖验证后写入支持矩阵，再开始对应实现。
- parser、Guardian、OpenList、Rclone、SQLite 按平台和架构固定版本与校验值，禁止把 Mac 资源混入其他平台包。
- 逐平台进行真实窗口、原生目录选择、强杀、卷变化、升级与完整下载→COPY→Emby 验收。历史三目标 CI 只作为定位和对照材料。

## 风险与取舍

平台文件系统和密钥存储差异 → 缺少安全能力就阻断相关操作，不模拟成功。平台数量扩大验证成本 → 逐目标交付，未完成目标继续列为待支持，不阻塞已验证平台。

## 迁移计划

承接主变更 1.4、4.1、8.1、8.2 中原有后续平台工作及平台扩展说明。保留原已完成记录；本变更任务均从未完成开始。实施前依据已落地主规格核对平台范围条款，必要时补完整 MODIFIED 增量，再扩展产物和 CI；失败产物不发布，用户数据沿用既有升级备份与兼容恢复流程。

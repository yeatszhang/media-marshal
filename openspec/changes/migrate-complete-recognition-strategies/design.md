# Design

## Context

详见 proposal.md。旧实现包含 Java 编排及 Python bridge，引擎已有 30 项 Python 回归。桌面已迁入部分确定性夹具但排除了 Codex；Core 独占 SQLite，Main 持有授权，Renderer 仅使用业务 IPC。

## Goals / Non-Goals

保留全部识别策略、原用例及典型 case；识别建议与文件执行分离。复用当前 COPY、首次授权及恢复机制，不恢复 Java 服务、HTTP 端口或旧数据库。

## Decisions

1. 将 Python 引擎和全部原测试迁到 tools/desktop-parser，冻结为现有解析器的独立 stdio 模式。普通 GuessIt 进程不加载模型业务；Codex 模式具有独立队列、超时、终止及运行目录。沿用算法与提示词，减少重写偏差。
2. Core 使用可替换的建议接口，构造最多四层父目录、80个同目录视频及规则／作品路径 scope；模型不接触媒体路径或 TMDB Key。生产使用冻结进程，测试注入假建议器。
3. 编排抽出共享识别策略，普通任务、主动单项、目录任务复用校验；Codex 证据保存在现有候选 JSON。持久批次保存目录重识别意图，关闭页面仍可查询。
4. 设置保存启用、CLI、模型、每日预算与置信度配置，默认保留旧值；取消强制确认历史开关。模型建议通过不替代现有自动策略样本授权。
5. 原 Python 测试直接迁入并运行；Java 测试按方法建立对照表，确定性用例转为当前可执行夹具，编排与文件约束用隔离 Core 集成测试复现。不得以列出旧方法名冒充用例已迁移。

## Risks / Trade-offs

- CLI 未安装／未登录 → 默认关闭，受控错误及人工入口，不在测试调用真实账号。
- 长调用与关闭 → 独立进程、请求取消及进程组清理，关闭排空，不影响普通解析。
- 旧文档与较新实现不符 → 以源码及测试为准，明确90%门槛及无固定审批。
- 同目录并发及批内冲突 → 冻结任务范围和版本，全部预览后核对坐标／目标再提交，保持逐项失败。
- 当前工作区并行改动 → 只提交本轮路径或精确差异，避免混入用户既有改动。

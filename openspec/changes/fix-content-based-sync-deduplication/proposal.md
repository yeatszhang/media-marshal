# Proposal

## Why

媒体整理会改变视频文件名，当前完整文件名加大小的候选索引使已有视频无法进入内容比较，造成重复下载。本次已只读核对三部剧的 22 个视频与媒体库精确字节数一致，合计 68.19 GiB。

## What Changes

- 按精确大小检索视频；本地来源与远端摘要优先按内容确认，不再要求同名。
- 无远端摘要时，按明确作品、季集、格式及大小弱比较，冲突或仅大小相同须核对；保留同名同大小的既有弱比较。
- 持久保存强弱依据、实际路径和文件身份；复用一次预览内的索引和摘要计算，弱比较不全读视频。
- 媒体库检查失败明确阻断，不静默当作缺失自动下载。
- 为暂停并到达安全点的未完成网盘同步任务提供重新核对，保留共享需求、完成历史和幂等边界。
- 图片、字幕及 NFO 独立处理。本次不增加持久全库索引，不修改真实媒体或自动调整个人下载队列。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `managed-cloud-downloads`：改名视频的强弱内容比较、可解释证据与现有作业安全重核。

## Impact

影响 Core 媒体库比较器、同步预览和作业、下载需求，contracts 的受限业务动作及 Renderer 同步任务操作；补充隔离测试、桌面窗口验证与当前架构说明。沿用现有 SQLite 所有权、目录授权与成功收据边界。

# Design

## Context

动机见 proposal.md。现有比较器仅按完整名称加大小索引，扫描与读取失败被吞掉，弱比较也重复全读视频。预览 JSON 已保存 LibraryFileEvidence；下载项由多个 download_job_item 需求共享，暂停与成功收据已有边界。

## Goals / Non-Goals

目标是修复候选遗漏、保留可核验依据并安全处理既有排队作业。本轮保持授权 Emby 本机目标边界，不增加在线识别、媒体删除或全库持久索引，不自动操作个人下载任务。

## Decisions

1. 按精确大小建立每次比较会话的候选索引。强比较只看大小及摘要；多路径命中同一摘要可确定性选择实际路径。用相同文件身份与快照合并摘要 Promise，一次流式读取同时计算 SHA-256 和所需远端算法；支持 AbortSignal。
2. 弱比较先校验明确身份冲突，再接受唯一同名候选或唯一作品/年份、季集、扩展名候选。作品从最近明确的作品目录或文件名提取，TMDB ID 双方都有时必须一致；不使用片名相似度、不发起在线识别。仅有大小候选或多个无法消歧候选返回可定位待核对原因。无候选则普通同步。弱证据保存文件快照、解析依据和时间，不计算伪强摘要。
3. 扫描不完整或已关联目录无法读取必须失败并展示目录路径与修复动作。区分没有关联目标（允许普通同步）与关联目标失联（不能据此自动下载）。检查读取错误只输出可信文案，不透传敏感底层响应。
4. 各次预览与确认在各自会话内复用比较器缓存；确认开启新的核验会话，强比较继续核对完整内容，弱比较核对快照和绑定。跨预览持久摘要缓存及索引另行优化，不为本轮引入数据库新旧双轨。
5. sync.recheck-library 是立即返回的业务动作：Core 在 app_setting 保存原作业的复核状态、请求身份、进度和结果，后台调度即使来源暂停也处理该复核。复核只读冻结范围；最后短事务复核来源生命周期、原预览及下载项状态，原子写入跳过证据并取消本作业对应需求。失败保留逐项原因且不部分撤销需求。复核期间拒绝恢复来源、删除/重试作业；重启从原冻结范围重新核对，保留已完成历史。下载所有者负责共享需求与物理项状态，不由同步服务直接接管在途传输。
6. 界面沿用任务详情，展示复核进度、结果与具体比较原因。按钮直接说明必须先暂停，复核不会解除暂停；接口不接受本机路径或私有授权。

## Risks / Trade-offs

- 无远端摘要不能证明内容相同 → 清晰标注弱证据、要求明确身份或同名，冲突待核对，保留显式重同步。
- 文件属性不变的异常替换无法靠弱比较检测 → 明示限制；强比较确认时仍读取完整内容。
- 持久全库索引尚未实现 → 一次预览共享索引、摘要去重、弱比较无大文件读取；扫描仍有界且错误可见。
- 长任务页面超时 → 复核请求只持久受理，现有任务轮询读取进度；中断可恢复。

## Migration Plan

沿用现有 JSON 证据及 app_setting 保存作业复核状态，无需清空个人数据库或迁移媒体。测试使用隔离目录与 SQLite；回滚代码不删除媒体与成功历史。现有任务由用户暂停后显式复核，不自动批量取消。

## 简写命名和人工核对

识别季目录 S1、Season 01 和第 1 季，并仅在有明确季目录时将纯数字视频名解释为集数。来源缺少年份时以季目录前的精确片名匹配全库作品；只有全部同名作品的年份与 TMDB 身份没有歧义才补全年份，同字节大小的单个候选不足以排除重拍作品。

疑似重复保存结构化候选及受管证据，公开响应只提供候选 ID、显示路径与大小，不能由页面提交本机授权或任意路径。人工跳过标为 USER_CONFIRMED 弱证据，执行前复核原文件和绑定；仍需同步只忽略本次预览的媒体库疑似匹配，仍遵守既有收据、在途复用、目标不覆盖及空间预算。决定限定在当前预览、文件和源版本内，不扩大为全局忽略规则；过期或应用配置改变拒绝旧决定。

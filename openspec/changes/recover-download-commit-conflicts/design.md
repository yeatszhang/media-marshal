# Design

## Context

CloudDownloads 以账号串行传输，但 reconcile 也按账号排斥。DownloadCommits 已支持根据停止证据及原文件身份继续提交和幂等记账；冲突仅保存 failure_code。列表只投影首个失败码。

## Goals / Non-Goals

提供已落盘文件的安全恢复与清晰反馈。保持暂停、取消、文件归属、不覆盖和成功收据边界。真实同名冲突通过用户移走占用文件或来源预览新位置解决，不引入自动覆盖／删除。

## Decisions

- 新增固定错误码，将可确认的失败条件存入原 failure_code；不转发异常原文或猜测历史 CONFLICT 的原因。
- 分页查询异常条目，返回应用 ID、相对路径、状态、失败阶段、规范化原因、核对资格及阻断说明；列表仅返回异常数量。
- 重新核对命令只接受 jobId/itemId，先验证归属；操作本身按条目合并，沿用原 attempt 和提交意图，天然可重复。命令立即返回，后台结果保留在条目失败记录中；重启继续原自动恢复。
- 自动与手动共用核对锁和安全检查，必须持有原 claim，原 attempt 已停止且有证据，不存在同条目或目标重叠的活动写入／核对。不同目标可与同账号传输并行。
- 自动失败后每分钟最多一次核对，手动可立即重试；核对锁覆盖关闭等待，失败不释放原 claim/intent。
- 有提交意图时只继续原提交，无意图时按旧流程清理已停止的暂存并回队列；手动核对入口仅用于有提交意图的条目。传输前目标占用解除后使用原下载重试。
- UI 分页展开异常，展示核对进度和阻断原因；成功后异常消失，计数及下载完成状态更新。

## Risks / Trade-offs

摘要核对有磁盘开销，使用条目锁、有限批次和失败退避控制；同一目标变更在文件层再次验证。历史通用 CONFLICT 只能说明阶段及未知具体原因，重新核对后才能记录精确原因。

## Validation

隔离真实文件验证已发布补记、暂存继续提交、外部同内容文件保护、文件变化、停止证据缺失、同账号并行及目标重叠、重复命令、重启、暂停／取消。契约测试拒绝路径等任意输入；组件与真实 Electron 窗口验证逐项反馈、操作更新、分页、920×640 和长路径。

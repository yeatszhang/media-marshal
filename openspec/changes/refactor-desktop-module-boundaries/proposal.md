# 桌面模块重构与自主开发基础设施提案

## Why

桌面的进程与包边界已经清楚，但业务职责集中、前端功能分散、压缩排版和旧配置接管增加了修改成本，已有日志与自动化又缺少统一的观察、操作和复现入口。需要完成有验收边界的内部重构，把架构约束和自主开发闭环一起落地，使 Codex 能基于当前构建定位问题、操作真实界面、修复并用可追溯证据验证，而不持续依赖人工转述报错和截图。

## What Changes

- 保留 Electron、React、三个现有 workspace、单一 Core 和 SQLite；按业务职责重组 Core，明确模块公开入口、依赖方向、表写入所有权及跨模块事务。
- 拆分 `IngestionPipeline` 的来源观察、候选接入、识别、计划、文件执行及恢复职责；执行与恢复共享持久状态机，保留预览、授权、幂等、暂停及崩溃恢复边界。
- Renderer 按功能聚合页面、模型、草稿、组件、文案和测试；拆出集中在 `services.ts` 中的模型，入口只负责组装。
- Main 按宿主能力拆分 IPC 处理器；Core 按业务注册命令；公开契约按能力组织并推导机械重复类型，仍显式暴露受限业务方法。
- 引入统一格式化、解析真实模块路径的依赖检查、数据访问入口检查、循环依赖检查、结构规模预算及带期限的存量例外；本地和 PR CI 使用相同命令，检查规则自身必须有正反例测试。
- **BREAKING**：按仓库 1.0 前数据策略，以当前业务模型直接初始化新数据库，停止 v1–v35 升级链和旧配置双轨接管；不支持的旧库保留原状并拒绝启动业务。旧格式备份不得恢复覆盖当前状态，当前格式的备份和文件恢复能力保留。实际删除已有数据须另行明确范围并获得确认。
- **BREAKING**：移除仅服务旧配置入口的公开动作、页面跳转和内部映射；保留当前同步、识别、下载、修正、清理及 Emby 能力。客户端各进程随同一构建更新协议，旧桥接不能静默访问新契约。
- 更新现有架构文档与 LikeC4 模型，使模块注册、职责和阅读入口一致；用分阶段任务及回归证据区分规划完成与实施完成。
- 在现有 Pino、源码映射和 Electron Playwright 基础上补齐跨进程关联日志、健康检查、构建指纹、确定性场景夹具与可恢复开发会话；提供统一 JSON 命令入口供 Codex 和其他开发工具调用。
- 提供 GUI 语义快照、截图及局部截图、受限操作、操作后状态验证与 macOS 原生辅助功能／窗口观察驱动，覆盖真实界面和原生菜单／对话框；明确实际支持、权限缺失和测试替身，避免把截图或 DOM 成功当成 OS 验收。
- 自动生成失败证据包与复现步骤，支持同场景修复前后验证、变化影响测试选择和资源回收；项目专属开发 Skill 将这些入口串成可重复流程。开发工具与故障注入不进入正式应用能力，不增加任意生产调试端口。

- 开发诊断默认以结构化日志、CDP 语义和业务后置条件为主；截图与视觉检查按需请求，不作为普通开发和非视觉验收的强制依赖。

## Capabilities

### New Capabilities

- `desktop-data-lifecycle`：当前数据格式的直接初始化、已有数据库准入、不支持格式的非破坏性拒绝，以及同格式备份恢复。
- `desktop-development-automation`：开发工具可依赖的会话控制、机器可读诊断、GUI 观察／操作、失败证据与重复验证接口，默认针对当前构建的隔离实例。

### Modified Capabilities

- `local-folder-ingestion`：修改「本地目录来源单向同步」中的历史配置自动迁移承诺；本地同步当前行为及其余识别、文件安全和恢复要求保持不变。

架构检查、格式化和目录重组属于工程设计与验收约束，写入 design 和 tasks；开发自动化新增的是供外部开发工具调用的明确行为契约，单独形成规格。其他四份主规格作为媒体业务回归基线，不产生无行为变化的 delta。

## Impact

- 代码范围：`apps/desktop/src/`、`packages/contracts/src/`、`packages/media-core/src/`，以及受路径、契约和初始化方式影响的桌面测试、构建配置与隔离夹具工具。
- 工程范围：根脚本、格式配置、依赖锁文件、现有边界检查与 GitHub Actions；新增 `tools/desktop-agent/`、共享桌面测试夹具和项目开发 Skill，macOS 原生驱动限开发工具。引入锁定版本的必要开发依赖，不更换应用框架或引入 ORM、消息总线、外部模型服务。
- 文档范围：`docs/architecture/` 当前说明、LikeC4 模型和必要的开发入口；不修改历史归档正文，不新增第二套进度日志。
- 数据影响：旧数据库及旧备份不再承诺可由新构建接管；清空后的新库不继承旧成功历史，不能自动接管原受管目录或推断文件归属。实现和验收默认使用隔离数据目录，不触碰个人媒体、凭据或正在使用的应用数据。
- 当前工作区已有日志和业务改动；本提案以现状为发现依据，实施须接续届时有效代码，不覆盖或混入其他任务未提交内容。本次只创建本变更规划文件。

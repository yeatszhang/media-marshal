# 桌面安装分发能力

## Purpose

当前向 macOS 用户交付包含完整运行依赖的客户端，其他平台保留扩展性与兼容，后续独立验收。明确版本兼容、升级备份和数据保留行为，让用户无需命令行即可安装和维护应用，同时避免升级或卸载影响已经下载及整理的媒体文件。

## ADDED Requirements

### Requirement: 可重现的应用框架依赖

应用框架 MUST 通过可校验、可追踪来源的固定包接入，并只使用公开导出入口。公开包尚不可用时 SHALL 保存仓库内构建包快照及可还原来源记录，使用相对包引用和锁文件；改用已发布包时 SHALL 固定精确版本并重新验证。正式构建 MUST 不依赖个人绝对路径、全局安装、跨仓软链接或上游未固定的工作树。框架 MIT 许可 SHALL 随第三方信息保留。

#### Scenario: CI 没有 wenger 源码仓库
- **WHEN** 干净环境只有 Media Marshal 仓库及锁定依赖可用
- **THEN** 能安装框架并构建客户端，包入口、DI 和 React 适配验证通过，不要求存在开发者个人目录

#### Scenario: 本机上游框架发生修改
- **WHEN** wenger 仓库源码更新，但本应用未显式更换框架包及锁文件
- **THEN** 本应用构建继续使用同一内容的已固定依赖；显式升级时记录来源和校验值并通过应用集成检查

### Requirement: 官网平台安装包

当前首发 SHALL 交付同一 Mac 客户端，优先 Apple Silicon，Intel 复用同一产品并单独验证；只为已通过对应验收的架构提供安装包。Windows 等其他平台 SHALL 不作为本轮 Mac 交付门槛，也不得未经完整验收宣传为已支持。官网下载页 MUST 显示应用版本、经验证的最低系统要求、架构、变更说明及校验值。当前阶段 SHALL 说明需要已有可用 Emby 和媒体库，新用户安装初始化属于后续能力；普通目录方式须说明外部下载前置条件，受管夸克下载所需组件 SHALL 随包提供，无需另装网盘客户端。

#### Scenario: 选择对应架构
- **WHEN** 用户打开官网下载页
- **THEN** 能辨认适用系统和架构、内置依赖及所选接入方式的外部前置条件，不必猜测下载哪个包

#### Scenario: Mac 已可内测而其他平台尚未交付
- **WHEN** Mac 已完成本阶段验收，但 Windows 等其他客户端或某个 Mac 架构尚未完成对应验收
- **THEN** Mac 已验证产物可以按内测或正式发行状态独立推进，不以未验收平台为前置条件，也不展示其可用下载入口或承诺已支持

#### Scenario: 安装客户端时已有 Emby
- **WHEN** 老用户在已有 Emby 和媒体库的 Mac 上安装 Media Marshal
- **THEN** 安装和首次使用允许直接接入该服务器及指定目录，不捆绑重装 Emby，也不重置已有服务器或媒体库配置

### Requirement: 可验证的发布产物

公开发布的 macOS 包 MUST 完成 Developer ID 签名和公证；应用、处理服务和解析依赖版本 SHALL 可追踪。功能验收、未签名内测包与正式发行 SHALL 分别记录，缺少签名配置时正式发行任务 MUST 保持未完成，不阻塞功能开发，也不把未签名包作为正式版本分发。发布流程 SHALL 校验包完整性。未来启用其他平台时 SHALL 补齐相应签名和安装态验收，Windows 代码签名不作为本轮 Mac 开发前置条件。

#### Scenario: 签名或公证失败
- **WHEN** 发布检查发现任一必需签名、公证或完整性检查失败
- **THEN** 该产物不进入正式下载渠道，并记录失败原因

#### Scenario: 尚无 Mac 签名配置
- **WHEN** 尚未提供 Developer ID 或公证配置，但已生成未签名 Mac 内测包
- **THEN** 能继续功能和内部安装验证，产物标明未签名状态，正式签名发行项仍未完成，不宣称已经公开发行

#### Scenario: 安装目录不允许应用写入
- **WHEN** 用户在受支持系统安装应用，安装目录不可写但用户数据目录可写
- **THEN** 包内 SQLite 原生模块和解析器依赖仍能运行，数据库及可变数据保存到用户数据目录，不要求在线补装运行时

### Requirement: 手动升级与活动任务协调

首版 SHALL 提供版本信息、官网发布说明和下载安装入口，通过用户手动替换安装包升级，不后台静默替换组件。升级前 MUST 让旧实例安全退出并备份数据库；恢复旧版本 SHALL 使用相容数据或对应备份，不直接打开新版本不兼容数据库。

#### Scenario: 有任务时准备升级
- **WHEN** 用户在文件复制期间选择退出并安装新版本
- **THEN** 应用先停止新接入并协调当前操作安全退出，保留恢复记录及升级前数据库备份

#### Scenario: 旧版本尝试读取更新的数据
- **WHEN** 旧版检测到不兼容的数据版本
- **THEN** 应用阻止写入并指导恢复对应备份，不自动降级修改数据库

#### Scenario: 数据库迁移失败
- **WHEN** 新版本在启动前检测到未知数据库结构或显式版本迁移失败
- **THEN** 停止新接入并展示恢复入口，保留一致性备份，不靠自动修改表结构继续处理文件

### Requirement: 自包含桌面产物与旧工程隔离

正式桌面包 MUST 只包含独立客户端及必要运行依赖，不以旧 Java/Vue/Docker 服务或产品账户为前提，不打包 JRE 和旧 HTTP 服务。应用 SHALL 携带适配目标平台及 Electron ABI 的 SQLite 原生模块和离线解析器。第一期 SHALL 不要求同步交付新的 Web 前端，也不读取旧服务端数据库或浏览器存储。

#### Scenario: 干净环境启动正式包
- **WHEN** 在未安装 Java、Node、Python 或编译器的目标系统安装正式包
- **THEN** SQLite 原生模块和离线 parser 可以运行，不在线补装运行时，不连接旧业务服务

#### Scenario: 电脑上存在旧 Docker 数据
- **WHEN** 用户首次启动客户端，电脑已有旧服务端数据库和规则
- **THEN** 客户端使用独立桌面数据目录并进入设置，不修改或自动导入旧数据库，也不自动扫描旧规则目录

#### Scenario: 旧 Web 工程未参与构建
- **WHEN** 通过 monorepo 的桌面构建命令生成安装包
- **THEN** 构建不依赖旧 Vue 构建或 Maven 产物，包内不存在旧产品入口和服务运行时；旧工程源码仍可独立保留

### Requirement: 卸载与媒体保留

卸载 MUST 不删除来源文件、目标媒体和用户数据；应用内单独提供的数据清理操作 SHALL 明示范围，不能把清理配置等同于清理媒体。重新安装兼容版本 SHALL 能识别保留数据。

#### Scenario: 卸载后检查媒体
- **WHEN** 用户卸载应用
- **THEN** 来源文件、Emby 媒体目录、任务数据库和备份仍存在

### Requirement: 发行说明与第三方信息

发行包 SHALL 包含第三方许可和元数据来源说明，清楚区分本地目录接入与通过验收的受管云端能力，不承诺网盘下载加速；尚未通过验收的云端订阅不得宣传为可用。公开收费版本 MUST 在发布前确认所用元数据服务适用的商业许可，不因用户填写自己的密钥而默认满足商用条件。

#### Scenario: 查看关于和来源帮助
- **WHEN** 用户查看关于页面和网盘接入说明
- **THEN** 可查看版本、许可和元数据来源，并了解普通目录接入处理本机文件，受管云端下载有独立授权与能力边界

# 开发态日志读取设计

## Context

安装的 electron-vite 支持 `REMOTE_DEBUGGING_PORT`。Main 仅采集有固定前缀的 Renderer 结构化日志。当前已有其他未提交日志改动，本次避免修改其实现。

## Goals / Non-Goals

提供独立、本机、显式连接的读取工具。不开启默认生产调试，不新增业务 IPC，不提供任意脚本执行，不实现统一开发会话或业务日志关联查询。

## Decisions

- 启动脚本仅向现有开发命令注入端口，不另建宿主；读取端固定连接 `127.0.0.1`，只接受本机 WebSocket 地址。
- 列出 page／webview 目标；单个 page 可自动选择，多页面或访客页面必须显式提供目标 ID，避免连接错误窗口。
- 使用原生 WebSocket 订阅 Runtime 和 Log；对象读取只取有界的自身数据属性，不调用 getter；未知异常只保留类型及调用位置。通过 Node 22 的类型擦除直接复用共享 TS 脱敏器。
- JSONL 输出包含目标和接收时间；连接、结束及丢弃均有结构化记录，历史完整性固定标为未知。命令超时、消息大小和待处理队列均有上限。
- 支持指定采集时长或 Ctrl+C；关闭时断开连接，不结束目标应用。对象是读取时的值，不声称打印时快照。

## Risks / Trade-offs

- Chromium 历史缓存不完整 → 明示未知，不将无错误日志视为通过。
- 页面导航导致对象失效 → 标明属性不可用，保留其他消息。
- 任意无标签秘密无法可靠识别 → 复用现有脱敏，文档提示仅采集所选开发窗口。
- 外部 CDP 与未来统一会话工具不同 → 独立规划与验收，不改动大重构任务状态。

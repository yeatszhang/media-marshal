# 桌面多语言设计

## 上下文

范围见 [proposal.md](proposal.md)。桌面已引入 i18next/react-i18next，并存在 `cloud-i18n.ts` 等中英文资源；主变更 7.1 的完成状态只代表当时基础已落地，不能证明新来源流程和全部宿主文案已双语验收。

## 目标与非目标

提供中文默认和英文可选的完整体验，覆盖语言持久化、回退和原生应用提示。不翻译用户输入或媒体路径，不改变 TMDB 元数据选择与模板命名，不要求新增更多语言。

## 决策

- 复用现有国际化资源与 React 订阅，集中维护稳定文案键、插值与缺失回退。不能以通用机器翻译运行时服务替代随包文案。
- 语言偏好通过现有受限设置契约保存，Renderer 和 Main 读取同一来源；语言切换只刷新显示，不销毁应用级 Application、重挂执行服务或重放保存命令。
- 业务层继续返回稳定错误类别和结构化参数，显示层决定翻译与格式；用户路径按原样展示，诊断仍遵守脱敏规则。
- 应用菜单、托盘和自主对话框文字使用同一词汇；OS 自有控件语言受系统控制，验收记录这一区别，不强行修改系统语言。
- 先完成所有页面中文键和英文资源对齐，再做双语组件及真实窗口验证。复用现有语言字段时保留合法已保存值，未知值回退中文。

## 风险与取舍

长英文和插值可能破坏布局 → 用实际错误、长路径与最小窗口验收。切换语言导致组件副作用重新触发 → 验证活动下载、待确认草稿和任务 ID 连续性。既有英文资源可能过时 → 按当前来源模型逐项核对，不将“有资源文件”当成覆盖完整。

## 迁移计划

承接主变更 7.6 的语言设置、20.3 的英文文案以及 desktop-runtime 的语言切换要求；媒体识别的中英文夹具仍留在主变更。实施前复核已归档规格中的中文范围并加入本扩展，逐页补资源和宿主通知；任务全部保持未完成，不能沿用 7.1 状态直接勾选。

# Emby 自动安装与初始化设计

## 上下文

范围见 [proposal.md](proposal.md)。现有 `packages/media-core/src/infrastructure/emby.ts` 和 ingestion 交付模块处理显式地址/API Key、库查询、刷新及收录核对，没有安装或首次账号创建能力。新增向导与安装适配不能被视为已有功能的小开关。

## 目标与非目标

首次以已支持的 macOS 为目标，提供可恢复的新实例安装初始化，再复用现有连接绑定与交付。不管理远程 NAS、容器部署、服务器自动升级或已有实例重配置。其他系统只在平台能力验收后扩展，不要求与此变更同时交付。

## 决策

- 采用独立安装作业和受限宿主动作，Renderer 提交用户确认后的结构化参数，不能提交 shell 命令或任意安装 URL。Main 管理系统安装和启动交互，业务层记录阶段与服务器绑定。
- 使用固定官方来源、版本和目标架构的产物清单，先核验再安装。此文不假定具体 Emby 版本的静默安装参数或首次设置 API 已验证；后续先固定产物与接口夹具，再接通执行动作，遇到产品行为差异先更新此方案。
- 安装状态与初始化状态分开记录，至少区分检测、待确认、下载核验、安装、启动、账号配置、库配置、连接核验及完成。每个外部副作用后保存证据，恢复时读回现状，不能仅依靠请求成功推断完成。
- 现有实例直接进入连接流程；新实例需明确用户选择，首次账号和目录参数由用户提供。密码仅在必要的受限调用中使用，持久密钥沿用系统保险箱。
- 初始化后调用已有服务器/媒体库绑定与交付服务。完成标记只表示安装初始化可用，不表示媒体已经收录。

## 风险与取舍

安装包许可、发行方式或首次设置能力可能变化 → 在实施时核对官方来源与实际版本行为，未验证部分保持阻断，不在本次规划冒充已验证。安装完成但初始化失败 → 保留可恢复记录，不卸载已有实例或删除媒体来伪装回滚。

## 迁移计划

承接主变更“新用户”后续说明，不移动其 6.x 既有服务器任务，也不复制已完成证据。实施前同步当时主规格中的“仅已有服务器”范围，在本扩展下明确新建入口；依次验证检测、安装、初始化和真实入库，取消或失败时保留已有实例及媒体。
